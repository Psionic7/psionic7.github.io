## 구현한 변경

### 1. 실거래 자료를 기준으로 통합 검색

- 빌드할 때 시군구별 거래 카탈로그를 합친 경량 검색 인덱스를 생성한다. 현재 로컬 자료에서는 594개 검색 항목을 생성했다.
- 지도 마스터에 없는 아파트도 검색·거래 조회할 수 있다. 연결이 검증된 단지는 마스터 ID·거래 키·별칭을 함께 유지한다.
- 이전 이름으로 검색해도 연결된 단지를 찾을 수 있고, 서로 다른 지번을 무조건 하나로 합치지 않는다.
- 검색을 시작할 때 인덱스를 한 번 받고, 이후에는 캐시를 공유한다. 전체 거래 파일이나 지도 경계는 검색에 필요하지 않다.
- 열린 페이지의 빌드 시점과 새 manifest가 달라지면 시군구 카탈로그로 호환 검색한다.
- 실제 브라우저에서 벽적골우성 1건, 주공그린빌3 1건, 꽃메마을힐스테이트 3건이 검색되며 선택한 단지 거래 패널로 이동함을 확인했다.

관련 파일: `src/search-index.mjs`, `src/HomeSearch.jsx`, `scripts/prepare-browser-data.mjs`, `server/browser-export.mjs`, `vite.config.js`.

### 2. 지도는 위치부터 표시하고 경계는 필요한 공간만 조회

- 원본 GeoJSON을 빌드 시 공간별 조각 28개로 나눈다. 경계를 쪼개거나 단순화해 좌표를 바꾸지는 않는다. 한 feature는 한 조각에만 들어가고, 셀 경계를 넘는 feature도 실제 bbox로 조회한다.
- 최초 지도는 단지 목록·위치만 받아 표시한다. 확대 14 이상에서 경계 옵션이 켜져 있을 때 현재 화면과 작은 여유 범위에 해당하는 조각을 받는다.
- 화면 밖의 경계·개별 마커는 생성하지 않는다. 낮은 확대의 동별 묶음 마커는 유지한다.
- 경계 파일 실패가 지도·단지 목록 전체를 막지 않는다. 위치와 목록은 남으며 경계만 재시도할 수 있다.
- 경계 파일은 최대 4개씩 요청하고, 최근 사용한 조각은 항목 수/크기 제한을 둔 캐시에서 재사용한다.
- 모바일 단지 목록 모드에서는 숨은 Leaflet 지도를 만들지 않는다. 목록 모드는 다음 방문에도 복원된다.
- 지도 타일의 일부 실패 상태를 개별 타일 단위로 추적한다.
- 지도 팝업·즐겨찾기는 유지한다. 실제 브라우저에서 별표 추가/해제 후 팝업과 지도 인스턴스가 남고 지도 pane의 위치가 바뀌지 않는 것을 확인했다.

관련 파일: `server/map-tiles.mjs`, `src/map-bounds.mjs`, `src/apartment-map-data.js`, `src/ApartmentMapCanvas.jsx`, `src/ApartmentMapPage.jsx`.

### 3. 외부 웹폰트 요청 제거

- Google Fonts CSS import를 제거하고 시스템 폰트를 사용한다.
- 문자 부분집합·폰트 CSS·글꼴 파일 요청이 없어지고 늦은 글꼴 교체에 따른 배치 이동을 줄였다.
- 수정본 측정에서 외부 폰트 전송은 0바이트였다. Windows·macOS·모바일 OS의 기본 한글 글꼴에 따라 글자 모양은 다소 다를 수 있다.
- 기존 색상·주요 컴포넌트·정보 구성은 유지했다.

관련 파일: `src/styles.css`.

### 4. 즐겨찾기·설정 복원과 저장 실패 알림

- 기존 262,144자 읽기 제한을 읽기·쓰기 공통 2,097,152자로 조정했다. 기존 대량 목록을 그대로 읽고 다음 설정을 저장해도 즐겨찾기가 사라지지 않는다.
- 새 쓰기가 제한을 넘거나 브라우저 저장소가 거부하면 기존 저장 문서를 덮어쓰지 않는다.
- 오류를 조용히 삼키지 않고 화면에 저장 실패 안내를 표시한다. 메모리에서 보이는 이번 변경은 창을 닫으면 남지 않을 수 있다는 점도 알린다.
- 기존 저장 키·형식·일반 사용자의 즐겨찾기는 유지한다. 로그인·서버 보관을 추가하지 않았다.

관련 파일: `src/preferences.js`, `src/StorageNotice.jsx`, `src/App.jsx`.

### 5. 모바일 거래 목록의 정보 도달 시간 단축

- 모바일 650px 이하에서는 페이지당 20건, 넓은 화면은 기존 50건을 제공한다.
- 거래 카드의 반복 여백·라벨 간격을 줄이되 계약일·이름·면적·층·가격·거래 상태/해제일은 유지한다.
- 동별 조회에서도 단지 조회와 같이 중복된 큰 상단 제목 공간을 줄인다. 제목 자체는 스크린리더가 읽을 수 있게 유지한다.
- 다음/이전 페이지를 누르면 거래 목록 시작으로 이동하고 초점을 복원한다.
- 320px에서 20건, 다음 페이지의 나머지 거래, 가로 넘침 없음, 긴 단지명을 확인했다.

관련 파일: `src/useMediaQuery.js`, `src/transactions/TransactionResults.jsx`, `src/ux.css`, `src/App.jsx`.

### 6. 장시간 사용·불안정한 회선

- 공통 JSON 캐시의 항목 수와 문자량에 한도를 두고 오래 사용하지 않은 완료 항목부터 제거한다. 사용 중인 화면이 참조하는 자료를 임의로 비우지는 않는다.
- 공유 중인 요청은 합치고, 실패한 요청은 캐시에 붙잡아 두지 않아 재시도할 수 있다.
- JSON 요청에 30초 제한과 복구 가능한 오류 메시지를 추가한다.
- 표시 중인 화면에서는 5분 간격 및 화면 복귀 때 게시 manifest를 확인한다. 새 자료가 있으면 알림을 표시하며 사용자가 누르기 전 조회 화면을 바꾸지 않는다. 숨겨진 탭에서는 확인을 미룬다.
- 새 자료를 적용해도 현재 URL의 조회 조건은 복원한다.

관련 파일: `src/json-cache.mjs`, `src/data.js`, `src/App.jsx`.

## 빌드·배포 자료 관리

- 검색 파일은 `public/query-data/`, 지도 조각은 `public/map-data/`에 생성하며 Vite 빌드가 `docs/`로 복사한다.
- 이 생성 자료는 기존 월별 파일과 같이 Git에서 제외하고 개발/빌드 스크립트에서 재생성한다. 원본 아파트 지도 자료는 유지한다.
- GitHub Actions의 기존 `pnpm build` → `pnpm check:publish` 순서에서 새 파일도 준비·검증된다.
- 공개 파일 검사는 검색 인덱스의 원본 해시, 지도 조각의 체크섬·파일 경로·건수·중복·유효 좌표·기존 단지 연결을 확인한다.
- 추가 계정, 외부 서버, 비밀키 설정은 필요하지 않다.

## 남은 범위와 주의점

- 로컬 자료는 2026-10-03 게시 스냅샷이다. 공개 사이트의 2026-10-18 게시 자료와 구분해야 하며, 이 작업에서 원천 데이터를 재수집하지 않았다.
- 실험실 측정은 필드 p75·공식 INP·실제 휴대전화 전체 검증을 대체하지 않는다. 각 기기의 타일 다운로드·폰트 표시·도형 수는 화면 범위에 따라 달라진다.
- 즐겨찾기 자동 계정 동기화/파일 백업, 식별자 중심 저장 형식 전환, 다중 탭 병합, 짧은 공유 URL, 단지별 SEO 페이지는 후속 선택 항목으로 남긴다.
- 전체 월 자료 호환 경로는 유지한다. 정상 빌드는 월별 자료를 사용하지만 아주 오래된 manifest와의 호환 상황은 별도 회귀 관리가 필요하다.
- 경계 조각을 받는 동안의 일부 네트워크 요청은 조회 변경 후에도 완료될 수 있다. 공유하는 요청을 임의로 중단해 다른 화면의 조회를 깨뜨리지 않도록 현재는 오래된 응답의 화면 반영만 차단한다.
- 문서·소스·빌드 결과를 수정한 상태로 남겨 두었으며 커밋·푸시는 하지 않았다.
