# 확인된 오류의 수정 계획 — 2026-10-18

기준: `4779aed`. 아래 계획에 따른 구현과 검증을 완료했다. 상세 근거는 [점검 보고서](BUG_AUDIT_2026-10-18.md), 실행 결과는 [수정 결과](BUG_FIX_RESULTS_2026-10-18.md)를 참조한다.

## 1. 불필요한 자료 요청 차단 — B01

- 날짜 유효성 검증 뒤 거래 요청을 허용한다. 카탈로그 전용 요청은 별도로 유지한다.
- 날짜를 비우거나 잘못된 범위를 입력하면 월별 거래 요청이 0개인지 검증한다.
- 정상 월·주·직접 기간 조회와 단지 검색 목록을 그대로 사용할 수 있어야 한다.
- 이미 시작한 이전 조회가 불필요하게 계속 다운로드되지 않도록 취소·구독 해제 방식도 검토한다. 공유 캐시를 사용하는 다른 화면의 요청을 함께 끊지 않도록 주의한다.

## 2. 저장 데이터 유실 방지 — B02, B07

- 즐겨찾기 변경을 최신 저장 데이터에 적용하고 `storage` 이벤트를 반영한다.
- 두 탭에서 서로 다른 단지·동을 추가한 뒤 두 항목이 모두 남는지 확인한다. 한 탭의 삭제가 다른 탭의 다음 저장으로 되살아나지 않아야 한다.
- 거의 동시 변경의 충돌 정책을 정하고 브라우저 두 탭으로 검증한다.
- 설정 원본을 읽을 수 없으면 조회 초기화와 되돌리기 스냅샷 저장을 중단한다. 원본 문서를 보존해야 한다.
- 크기 초과·접근 거부 상황에서 실패 안내가 나오고 즐겨찾기가 지워지지 않는지 검증한다.

## 3. 화면 로딩·자료 구조 오류 복구 — B03, B04

- 지연 로딩 화면에 오류 경계를 두고 메뉴·안내·복구 버튼을 유지한다.
- 배포 후 이전 JS 청크가 없어지는 상황과 일시 네트워크 실패를 주입한다. 본문 전체가 사라지지 않고 복구할 수 있어야 한다.
- 루트 manifest의 필수 구조를 검증하고 실패를 자료 로드 오류로 처리한다.
- `{}`, 잘못된 필드 타입, HTTP 오류, 정상 응답 각각을 검증한다. 새로고침 반복이 발생하지 않아야 한다.

## 4. 결과와 공유 조건의 일관성 — B05, B06

- 대시보드·지도·조회 화면의 자료 제공 판정을 통일한다.
- 현재 메타데이터로 확인할 수 없는 상태를 0건과 구분한다. 수집 완료한 동·월을 명시하는 메타데이터의 도입 범위도 정한다.
- 공유 URL을 저장소 대신 현재 필터 상태로 생성한다.
- 저장 쓰기가 실패해도 면적·평대·해제 거래 포함·단위가 URL과 화면에서 일치하는지 확인한다.

## 5. 관리자와 수집 경로 정리 — B08, B09, B10

- 설정 확인 버튼을 기존 상태 재조회 API에 연결하고 화면 클릭부터 응답까지 검사한다.
- 관리자·CLI의 빌드 진입점을 통합한다. 별도 임시 체크아웃에서 준비 자료가 없는 상태와 원본 지도 갱신 상태를 빌드한다.
- 최종 지도·검색 생성물의 존재 및 버전 일치를 게시 검사에 포함한다.
- 건축물대장 API의 재시도 횟수 기준을 통일하고 모든 소진 경로에서 명확한 오류를 던진다.
- 네트워크 실패·본문 읽기 실패 혼합, 마지막 시도 성공, 사용자 취소를 가짜 응답으로 검사한다. 인증키나 실제 호출 한도를 사용할 필요는 없다.

## 완료 판단

각 오류의 재현 테스트가 수정 전 실패하고 수정 후 통과해야 한다. 해당 변경을 반영한 뒤 기존 `pnpm test:all`, 공개 빌드·게시 검사를 실행한다. 화면 변경은 모바일 실제 브라우저에서 확인하고 로컬 미리보기를 연다. 커밋·푸시는 해당 수정 작업에 대한 사용자의 명시적인 요청이 있을 때만 진행한다.
