# 아파트·동 실거래가 화면 통합

## 분석

대시보드는 WeeklyPage를 즐겨찾기 모드로 사용해 여러 아파트를 보여주지만 즐겨찾기를 자동으로 모두 조회한다. 아파트별 탭은 별도의 지역·계약월 선택과 단일 아파트 상세/그래프/통계 화면을 사용한다. 결과 표도 날짜·면적·컬럼 구성이 서로 다르다. 개인 아파트 즐겨찾기에는 공식 대장 단지 ID 및 확정 거래 별칭이 있어 단순 이름으로 합치면 안 된다.

## 계획

1. 공통 기간·면적·기타 옵션과 결과 표시를 TransactionPage/TransactionResults로 분리해 아파트/동 기준만 바꾼다.
2. 아파트별 탭의 3번 필터를 즐겨찾기 아파트 선택과 지역·아파트 검색 선택으로 구성한다. 조회 선택과 즐겨찾기는 별도로 저장하며 여러 지역을 함께 조회한다.
3. 기존 즐겨찾기 및 대시보드 기간·면적 설정을 보존하고 기존 대시보드 링크를 통합 화면으로 연결한다. 이전 지역/계약월 링크도 수용한다.
4. 유효 거래 등 4개 카드와 기존 단일 아파트 통계/그래프를 제거한다. 두 기준 모두 계약일·아파트명·전용평·층·거래금액·해제 상태를 동일한 표로 표시한다.
5. 같은 이름의 다른 동·지번, 공식 단지 거래 별칭, 즐겨찾기와 조회 선택 분리, 복수 지역 캐시·실패·미수집, 저장/URL 복원, 페이지 이동·기간·면적·해제 거래, 모바일 화면을 검증한다.

## 구현 결과

- 기존 대시보드 탭을 아파트별 실거래가 탭으로 통합했다. 이전 dashboard 주소와 저장된 탭은 아파트별 조회로 연결한다.
- 1번 기간, 2번 면적, 4번 기타 옵션은 두 조회 화면이 동일한 TransactionPage를 사용한다. 3번은 아파트 또는 동 선택 컴포넌트로 구분했다.
- 아파트 선택에는 개인 즐겨찾기 체크박스, 선택한 아파트 목록, 기존 지역 선택·검색, 아파트명·주소·동·지번 검색을 제공한다. 여러 시군구·아파트를 선택한 순서로 비교한다.
- 별표는 즐겨찾기 저장을, 체크박스는 실거래 조회 선택을 처리한다. 조회에서 제거해도 즐겨찾기는 남고, 즐겨찾기를 해제해도 이미 선택한 조회 결과는 유지된다.
- 아파트 검색은 선택한 지역의 전체 수집 자료를 사용한다. 조회 기간에 거래가 없는 단지도 선택할 수 있고, 큰 목록은 100개씩 더 보기로 제공한다.
- 기존 개인 아파트/지역 즐겨찾기 저장과 공식 대장 단지의 확정 거래 별칭을 유지한다. 같은 이름의 다른 동·지번은 구분하고 같은 단지/별칭의 중복 조회를 막는다.
- 거래 결과를 TransactionResults로 공통화했다. 계약일 YY.MM.DD, 아파트 이름, 전용평 소수 첫째 자리, 층, 억 원 금액, 거래 상태/해제일의 6개 컬럼을 동일하게 표시한다. 두 화면 모두 50건씩 페이지를 나눈다.
- 유효 거래 등 4개 요약 카드와 기존 단일 단지 통계·그래프 화면을 제거했다. 결과 제거는 즐겨찾기 해제가 아닌 조회 제거다.
- 아파트 선택·검색·기간은 apartmentTransactions/apartmentSearch에 저장하고 동 조회의 weekly/explorer 설정과 분리했다. 공유 URL에는 선택 아파트와 기간을 포함하며 다른 브라우저에서도 복원한다.
- 이전 대시보드의 기간·면적 설정과 저장된 단일 아파트 선택을 수용한다. 이전 start/end 계약월 링크는 공통 직접 지정 기간으로 변환한다.

## 구조와 최적화

- src/TransactionPage.jsx: 공통 기간·면적·기타 옵션, 자료 로딩 및 결과 배치.
- src/transactions/TransactionResults.jsx: 공통 거래표와 페이지 이동.
- src/transactions/ApartmentSelector.jsx: 즐겨찾기와 지역·아파트 검색을 통한 복수 선택.
- src/weekly/DongSelector.jsx: 기존 동 검색·즐겨찾기 동 선택.
- src/apartment-query.js: 조회 아파트 검증, 공식 단지 별칭 변환, 저장값/공유·이전 링크 복원.
- 기존 Dashboard, ApartmentExplorer, WeeklyResults의 중복 화면 코드를 제거하고 WeeklyPage/ApartmentPage는 각 기준을 공통 화면에 연결한다.
- 검색과 조회는 필요한 시군구 자료를 같은 캐시에서 읽는다. 검색 단지 목록 생성은 자료/지역이 바뀔 때만 계산하고, 면적 슬라이더 상한은 같은 시군구에서 한 번만 계산한다.
- 기존 그래프 코드가 공개 화면에서 빠졌다. 빌드의 아파트 화면 전용 JS는 약 399KB에서 약 8.7KB로 줄었으며 두 조회 화면이 약 18.2KB의 공통 조회 코드를 함께 사용한다. 수치는 압축 전 개별 번들 크기다.

## 검증 결과

- React 테스트 13개 파일, 78개 테스트 통과. 동 조회 회귀, 여러 아파트/동·지번 구분, 확정 거래 별칭, 즐겨찾기와 조회 분리, 공유/저장·이전 링크 복원, 기간 독립성, 면적·해제 거래, 페이지 이동, 미수집·실패·늦은 응답 처리를 검사했다.
- 공개 빌드 통과, 공개 파일 검사 통과: 197개 파일.
- 실제 배포 빌드의 로컬 페이지 HTTP 200, 대시보드 이전 주소 연결, 풍덕천동 보원/동보 단지 검색과 복수 선택, 별표 저장과 체크 상태 동기화, 두 조회 탭의 동일한 표 형식을 확인했다.
- 접기·펼치기, 새로고침, 저장값 없는 다른 브라우저에서 공유 URL 복원, 아파트/동 선택의 독립성, 선택 모두 해제 후 즐겨찾기 유지도 확인했다.
- 모바일 390px·320px에서 가로 넘침 없이 체크박스 선택·해제가 가능했다. 데스크톱 및 390px 화면을 시각적으로 확인했고 브라우저 스크립트 오류는 없었다.
- 변경 차이의 공백 오류 검사 통과. 구현·검증 완료 후 사용자의 후속 요청에 따라 변경 사항을 커밋·푸시 대상으로 포함한다.

## 요약

아파트별 실거래가는 즐겨찾기 또는 지역 검색에서 여러 아파트를 골라 조회하는 통합 화면이다. 동별 조회와 필터/거래표를 같은 구현으로 사용하며 기준만 아파트 또는 동으로 달라진다. 요약 카드 대신 실거래 목록에 집중하고 개인 즐겨찾기는 그대로 보존한다.
