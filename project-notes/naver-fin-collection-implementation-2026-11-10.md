## 실패 원인과 수정

기존 수집기는 `new.land.naver.com`의 상세 URL·요소·`/api/...` 응답을 전제로 했다. 실제 Chrome에서 이 주소가 `/404`로 이동했다. 현재 `fin.land.naver.com`은 상세 선택 상태를 `/map?layer=...`로 옮기고 새 API·데이터 형식을 사용한다.

또한 기존 전체 수집 함수는 새 문서로 이동했는지 확인하기 전에 이전 화면을 오류로 판정할 수 있었다. 단지 정보 확인 함수와 전체 수집 함수 모두 새 문서의 로더를 확인하도록 맞췄다. 처음에 사이트 홈을 열어 생기던 이전 화면도 피하도록 임시 탭은 `about:blank`에서 시작한다.

수정한 내용은 다음과 같다.

- `scripts/naver-system-chrome.py`: 현재 화면의 `articleTradeTypes=A1` 매매 목록을 열고, 브라우저가 실제로 받은 `/front-api/v1/complex/article/list` 응답과 공개 요청 범위를 읽는다. 스크롤로 다음 페이지 요청을 발생시킨다. 쿠키·인증 헤더·사용자 프로필을 추출하거나 API 요청을 재생하지 않는다.
- `server/naver-fin-listings.mjs`: 서버 렌더링 JSON에서 요청한 공식 단지번호의 정보를 읽고 주소·좌표를 공통 검증기에 전달한다. 응답의 `lastInfo`, `hasNextPage`, `totalCount`로 페이지 연결과 완료를 확인한다. 페이지 누락, 총수 변경, 커서 반복, 잘못된 단지, 중복 광고, 누락된 중개사 광고는 실패시킨다.
- `server/naver-system-chrome.mjs`: 기본 서비스를 새 도메인으로 전환한다. 현재 응답 형식을 위 검증기로 전달한다. 기존 응답을 사용하는 로컬 회귀 테스트 경로는 유지한다.
- `src/naver-listings.mjs`: 새 단지 링크를 생성하고 이미 저장된 구도메인 링크·관측도 읽는다. 광고 상세 링크는 `fin.land.naver.com/articles/<광고번호>`를 사용한다.

새 응답의 가격은 원 단위다. 원문 값이 만원 단위로 정확히 나누어지는지 검사한 뒤 저장 형식으로 변환한다. 전용·공급면적, 건물 동, 층, 확인일, 방향, 중개사를 보존한다. 아파트 `A01`과 재건축 `A04`는 각각 기존 `APT`, `JGC` 분류로 변환한다.

네이버 제공 묶음은 응답의 `representativeArticleInfo`와 `duplicatedArticleInfo.articleInfoList`만 사용한다. 가격·동·면적·층이 같다는 이유로 다른 광고를 묶지 않는다. 저장하는 관계 키는 기존처럼 `<단지번호>:<대표광고번호>`다.

## 일일 수집은 승인 기준을 수정하지 않는다

일일 수집에서는 `apartment_naver_matches`의 활성 `verified` 연결 중 현재 범위 해시와 일치하는 번호만 사용한다. `--force`, `--retry-unresolved`도 미확정 연결을 승인하거나 새 번호를 검색하는 권한이 아니다.

수집 중 아파트 기준·별칭을 다시 만들거나 스냅샷에서 연결을 자동 승인하던 경로를 제거했다. 거래의 조회용 주거 식별 자료만 기존 아파트 정보를 읽어 재생성한다. 성공 자료는 매물 저장 영역에 저장하며, 실패는 수집 이력과 이전 관측의 실패 상태로 기록한다. 주소 불일치·검색 미확정·일시 오류가 생겨도 아파트의 네이버 번호와 승인 연결을 지우지 않는다.

수집 보고서에는 `sourceVersion=fin-land-v1`을 기록한다. 옛 서비스의 당일 성공·실패 보고서로 새 서비스 수집을 건너뛰지 않으며, 같은 버전의 당일 시도는 기존 재개 규칙을 따른다.

이 수정은 GitHub로 전달할 독립 기준본의 전체 버전 이관이나 실거래 공식 단지번호 이관을 완료한 것이 아니다. 해당 차이는 [데이터 운영 규칙](data-ownership-and-provider-identities.md)에 계속 남아 있다.

## 재실행 명령

nodriver가 설치된 Python 3.12를 `NAVER_BROWSER_PYTHON`으로 지정한 뒤 실행한다.

```powershell
pnpm listings:verified --complex-no 2645
```

이 명령은 원본 DB를 읽기 전용으로 열고 범위가 유효한 확정 연결만 찾는다. 실제 수집 결과·보고서·원문은 기본적으로 `local/naver-current-collection/`에 저장한다. 기존 마지막 성공 결과는 실패 실행으로 덮어쓰지 않는다. 실패 원문은 별도 시도 파일로 남긴다. 공개 파일 내보내기·커밋·푸시는 실행하지 않는다.

여러 단지를 저장 지역 기준으로 수집할 때는 기존 `pnpm listings:daily`를 사용한다. 일일 명령은 DB의 매물 저장 영역을 갱신하므로 복사본 검증과 기준본 확인을 먼저 수행한다.

## 원본 대조와 DB 저장 검증

실제 원문에서 읽은 광고 ID 255개가 정규화 결과에 모두 있는지 확인했다. 각 광고의 원 단위 호가, 전용면적, 공급면적, 동, 층을 저장값과 대조했다. 대표 광고와 하위 광고의 명시적 관계로만 묶음 키를 생성했다.

`local/naver-current-collection/working.sqlite3`는 현재 로컬 DB의 일관된 백업이다. 이 복사본의 `naver_listing_snapshots`에 실제 결과를 저장하고 다시 읽어 비교했다. 한 단지에 대한 수집 보고서도 복사본에 저장했다.

- 아파트·주소·확정 연결 관련 26개 테이블은 원본과 수집 전후 SHA-256이 같다.
- 실거래 344,494건은 변경하지 않았다.
- 원본 DB는 읽기 전용으로 사용했고 변경하지 않았다.
- 복사본 `PRAGMA quick_check` 결과는 `ok`다.

전체 원문은 비공개 `2645-source.jsonl`, 정규화 자료는 `2645.json`, 외부 수집 시도 결과는 `2645-report.json`, 원본 대조 결과는 `verification.json`에 있다. 감사 명령의 상세 결과는 같은 디렉터리의 `apartment-matches.json`과 `apartment-matches.md`다. 이 원문·DB 파일들은 Git에 포함하지 않는다.

- Node 회귀 테스트 331개 통과.
- 화면 테스트 182개 통과.
- 데이터 무결성 테스트 24개 통과.

- `pnpm build`의 빌드 전후 데이터 검사와 `pnpm check:publish` 406개 파일 검사 통과.

초기 진단의 일부 실행에서는 새 서비스가 HTTP 429를 반환했다. 이 오류를 단지 연결 오류나 매물 0건으로 저장하지 않았다. 정상 일반 Chrome 실행에서 실제 매물 응답과 마지막 페이지를 확보한 뒤 위 결과를 검증했다. 정기 실행 환경에서도 접근 제한은 별도 실패로 기록하고 중단한다.

로컬 앱 미리보기는 <http://127.0.0.1:5173/?tab=apartments>다. 이번 실제 수집의 광고 255건을 검색해 볼 수 있는 별도 검증 화면은 <http://127.0.0.1:8791/>다. 원본·공개 스냅샷의 매물을 이번 한 단지 검증 자료로 덮어쓰지 않았다. Codex 브라우저 패널 열기 요청은 도구에서 `queued`로 반환됐다.
