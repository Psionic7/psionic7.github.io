# 데이터 수집·추출 필수 검증 — 2026-10-18

## 분석과 적용 계획

기존 수집기는 API 총건수·페이지 존재·필드를 확인했고, 공개 파일 검사는 주로 체크섬과 총건수를 확인했다. 하지만 총건수를 유지한 계약 교체, 동일 계약 한 건의 소실, 원문만 손상된 저장, 조회 목록·지도 연결의 손실은 각 단계의 정상 출력처럼 보일 수 있었다. 수집 직전·추출 직후·빌드 전후에 거래별 대조를 필수로 연결하고, 이를 우회하지 않는 회귀 테스트를 추가했다.

## 적용한 검사

1. **수집 트랜잭션 안의 검증:** 저장된 API XML을 다시 파싱·정규화해 실제 DB와 대조한다. 총건수가 같아도 거래가 바뀌거나 원문 필드가 손실되면 거래·수집 이력·원천 페이지 전체를 롤백한다. 동일한 계약은 개수까지 보존한다. 반복·누락된 페이지도 거부한다.
2. **급감 방지:** 기존 거래가 있는 월의 0건 응답과, 기존 100건 이상인 월이 절반 미만으로 줄어드는 응답은 자동 교체하지 않는다. 실제 원천을 확인해야 하는 실패로 처리한다. 소규모 정상 정정·삭제, 처음 수집하는 실제 빈 달은 허용한다.
3. **작업 DB 검증:** 모든 계약월의 최신 저장 원문과 DB를 대조하고, 원문 정규화 값·현재 행·수집 이력의 건수를 확인한다. 수집 이력이 사라진 계약월이나 원문 페이지가 없는 경우도 실패한다.
4. **추출 직후 필수 검증:** 공개 SQLite·지역별 JSON·월별 조회 파일·단지 검색 목록·최근 유효 거래를 서로 대조한다. ID·계약월·날짜·단지·동·지번·금액·면적·층·준공연도·해제 상태·해제일·원문 전체·주소를 각 출력 형식의 계약에 맞춰 확인한다. 압축·해제 체크섬과 DB 무결성도 검사한다.
5. **검증 후 반영:** 임시 폴더에 산출물을 만든 뒤 실제 검증기가 통과해야 공개 파일을 교체한다. 검증 실패 시 이전 공개 manifest·SQLite·조회 manifest를 보존하는 테스트를 추가했다.
6. **빌드 전후 검증:** 조회 파일 준비 직후 `public/`을 검사하고, Vite와 마무리 작업 후 `docs/`를 다시 검사한다. 통합 검색의 거래 식별자 누락·충돌, 지도 단지 누락, 확인된 거래 키 손실, 공개 후보가 있는 모호한 연결도 실패 처리한다.

계약 비교는 SHA-256으로 정규화한 행의 **다중집합**을 비교한다. 행 수나 고유 거래 키만 비교하지 않는다. SQLite의 ID가 없는 원천 응답은 거래 필드와 모든 원문 필드로, 공개 출력은 ID까지 포함해 비교한다. 원문의 키 순서는 비교 결과에 영향을 주지 않는다. 필수 필드의 생략과 명시적인 `null`도 구분한다.

## 모든 실행 경로에서 강제

- `exportData` 자체에 검증을 넣어 CLI·로컬 관리자·GitHub Actions가 같은 검사를 수행한다. 검증 생략 옵션은 추가하지 않았다.
- `pnpm data:export`는 검증을 마친 산출물만 반영한다. 추출 직후 통합 검색은 아직 준비 전이므로 기본 데이터 검사를 먼저 수행하고, 검색·지도 검사는 빌드에서 필수 실행한다.
- `pnpm data:verify`로 실제 추출 결과를 별도로 다시 검사할 수 있다.
- `pnpm build`와 로컬 관리자의 공용 빌드 파이프라인에는 빌드 전·후 검사 모두 필수로 연결했다. 어느 단계든 실패하면 명령이 실패한다.
- Actions는 추출 직후 데이터 회귀 테스트를 반드시 실행하고, 추출·회귀 테스트·빌드 검증 실패 시 암호화 DB 저장과 Pages 업로드·배포로 넘어가지 않는다. 검사 요약은 `data-validation` 아티팩트로 성공·실패 모두 14일 보관한다.
- 앞으로의 작업에서도 검사하도록 `AGENTS.md`에 실행 규칙을 남겼다.

## 검증 결과

- 신규 데이터 회귀 테스트 **16개**. `pnpm test:data`는 기존 감사·브라우저 출력 테스트를 포함해 **22개**를 실행한다.
- 전체 Node 테스트 **120개**, UI 테스트 **119개**, 총 **239개** 통과.
- 대용량 검사와 병렬 실행한 UI 테스트에서 5초 시간 초과 1건이 있었으며, 대용량 작업 종료 후 전체 테스트를 단독 재실행해 모두 통과했다.
- 실제 **343,552건 / 3개 구 / 757개 월별 파일**, 최신 저장 원문 **939개 구·월 / 982페이지**를 대조했다.
- 기존 공개 자료 검사뿐 아니라 전체 실제 데이터를 `local/data-integrity-full-export/data`에 새로 추출하고, 추출 함수의 필수 검사와 별도 추출 후 검사를 실행했다. 검증을 마친 임시 추출물은 삭제하고 검사 요약을 보존했다. 운영 사이트·추적 중인 데이터 파일을 새 수집 자료로 교체하지 않았다.
- 빌드 전후 통합 검색 **612개 거래 식별자**와 지도 범위·연결을 검사했다. 공개 빌드와 게시 파일 검사도 수행했다.
- 일부러 동일 건수의 계약·공개 DB를 변조하고 체크섬까지 다시 생성한 경우, 월별 중복 행 제거·금액·면적·층·주소·해제일 변조, 검색 목록 손실, 지도 연결 손실, DB 트리거에 의한 저장 손실을 재현해 실패와 데이터 보존을 확인했다.

현재 검사 요약은 `local/data-validation/`에 저장한다. `full-export.json`은 필수 추출 검사, `after-full-export.json`은 별도 추출 후 검사, `public.json`과 `build.json`은 빌드 전·후 검사다. 요약에는 API 키·개인 즐겨찾기·원문 거래를 담지 않는다.

주요 검증 요약은 [증거 JSON](DATA_INTEGRITY_EVIDENCE_2026-10-18.json)에도 남겼다.

## 검사의 기준

자동 수집 환경에서는 복원한 작업 DB와 저장한 API 원문이 기준이다. 원본 DB가 없는 새 체크아웃에서는 공개 SQLite를 기준으로 출력 간 일관성을 확인하고, 보고서의 `source`에 이 기준을 표시한다. 검사 과정에 추가 API 호출은 없다. 원천에 나중에 신고·정정·해제되는 거래는 기존 최근 12개월·과거 순환 수집 정책으로 반영한다.

이번 요청에는 커밋·푸시가 포함되어 있지 않으므로 수정과 검증까지만 수행한다.
