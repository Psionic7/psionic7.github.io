# 즐겨찾기 아파트의 네이버 부동산 매물

작성: 2026-11-06. 대상: `psionic7.github.io` React/Vite 공개 앱.

## 목표와 현재 구조

브라우저의 `viewer.apartments` 즐겨찾기에 있는 아파트의 네이버 매매·전세·월세 광고를 대시보드에서 확인한다. 실거래 데이터와 호가를 섞지 않는다. 단지 이름이 같아도 지역·지번이 다르면 다른 단지다. 즐겨찾기의 기존 ID와 저장 형식은 유지한다.

공개 사이트는 GitHub Pages 정적 호스팅이고 즐겨찾기는 사용자 브라우저에만 있다. 브라우저에서 네이버 내부 API를 직접 호출하는 방식은 CORS·인증 및 요청 제한 때문에 채택하지 않는다. 모든 이용자의 즐겨찾기를 임의로 중앙 서버에 업로드하거나 기존 예약 수집 설정으로 바꾸지 않는다.

## 사전 조사와 확인된 제약

- [NAVER Developers 공개 API 목록](https://developers.naver.com/products/intro/plan/plan.md)에는 부동산 매물 조회 전용 API가 없다.
- 이 PC에서 2026-11-06 확인한 `new.land.naver.com/api/articles/complex/111515`는 HTTP 429를 반환했다. 모바일 조회 경로는 JSON `null`을 반환했다. 둘 다 실제 매물 수집 성공의 증거가 아니다.
- 연결 구현은 네이버 웹 서비스의 내부 응답 형식에 의존하므로 서비스 변경 시 수정이 필요하다. 401·403·429는 즉시 중단하고 제한 시간을 표시한다. 프록시 회전, 브라우저 인증 탈취, CAPTCHA 우회, 대체 호스트로 차단 우회는 구현하지 않는다.
- 운영 환경의 실제 응답이 성공하기 전에는 “실시간 수집 검증 완료”라고 보고하지 않는다. 테스트용 광고는 공개 데이터에 넣지 않는다.

## 선택한 설계

1. **단지 연결**: 각 즐겨찾기에 네이버 단지 URL 또는 번호를 입력한다. 별도 `naverListings` 설정에 저장한다. 수집 전에 단지 상세의 시군구·법정동·지번 또는 도로명주소가 즐겨찾기와 일치하는지 서버에서 검증한다. 이름만으로 자동 연결하지 않는다. 다른 단지를 입력하면 수집하지 않는다.
2. **수집 서버**: Vite 개발·미리보기 서버에 로컬 전용 `/api/naver-listings/*`를 추가한다. Host·Origin·JSON 요청·크기를 검사한다. 외부 요청 대상은 네이버 고정 호스트이며 토큰은 서버 환경변수 `NAVER_LAND_AUTHORIZATION`에서만 읽는다. 토큰을 설정하지 않은 요청도 가능하되 인증이 필요하면 실패로 표시한다.
3. **수집 계약**: APT, 매매(A1)·전세(B1)·월세(B2)를 광고 번호별로 전체 페이지 수집한다. 종료 상태 광고를 제외하고, 페이지 반복·ID 충돌·잘못된 응답·중간 페이지 실패를 발견하면 그 단지의 새 스냅샷을 확정하지 않는다. 중개사가 다른 동일 주택 광고를 같은 물건으로 추정해 합치지 않는다.
4. **캐시와 실패**: 단지별 5분 캐시, 서버 요청 간격, 요청 시간 제한·페이지 상한·429 대기 시간을 둔다. 검증된 완전한 스냅샷만 원자적으로 로컬 저장한다. 실패 시 마지막 성공 자료를 유지하되 최신 결과와 구분한다. 연결을 바꿨다면 이전 단지 자료를 재사용하지 않는다.
5. **대시보드**: 관심 아파트마다 연결·수집 상태·수집 시각을 표시한다. 전체 수집 진행률, 매매/전세/월세·면적·가격 정렬, 광고 표와 페이지 이동, 네이버 원문 링크를 제공한다. 저장된 자료가 24시간 이상이면 오래된 자료로 표시한다. “0건”, “미수집”, “연결 오류”, “이전 수집 결과”를 구분한다. 실제 현장 매물 존재·거래 가능 여부를 보증하는 표현은 쓰지 않는다.
6. **정적 사이트와 CLI**: 브라우저에서 현재 즐겨찾기와 단지 연결을 수집 대상 JSON으로 내려받는다. `pnpm listings:collect --targets <파일>`로 같은 수집기를 실행한다. 기본 출력은 비공개 `local/naver-listings-snapshot.json`; `--output public/listings/snapshot.json`을 명시하면 정적 화면용 결과를 만든다. 기존 빌드가 이를 복사한다. GitHub Pages는 저장된 결과를 읽고, 로컬 수집 서버가 없을 때 원격 실시간 수집 버튼은 제공하지 않는다. 임의의 원격 수집 서버는 이번 범위에 포함하지 않는다.

## 모듈과 데이터 계약

- `src/naver-listings.mjs`: 단지 URL/번호, 연결·스냅샷 검증, 상태·신선도, 광고 필터·정렬.
- `server/naver-listings.mjs`: 네이버 단지 주소 검증, 광고 정규화·페이지 완전성, 제한·캐시·원자 저장.
- `server/naver-listings-api.mjs`: 로컬 HTTP 경계, Vite 플러그인.
- `src/FavoriteListings.jsx`와 CSS: 기존 대시보드 아래 독립 영역. 즐겨찾기 추가/삭제를 그대로 반영.
- `scripts/collect-naver-listings.mjs`: 브라우저가 내려받은 대상 파일의 검증·순차 수집·스냅샷 출력. 실패가 하나라도 있으면 종료 코드 1.
- `tests/naver-listings.test.mjs`, `tests/favorite-listings.test.jsx`: 수집기·HTTP·실제 사용자 동작 회귀 검증.

스냅샷은 `{version:1, source:'naver-land', generatedAt, groups:[...]}`. 그룹에는 즐겨찾기, 단지 번호·이름, 마지막 시도/성공 시각, 상태, 공개 가능한 정규화 광고만 포함한다. 인증 값·응답 원문·브라우저 설정 전체는 저장하지 않는다. 광고는 `id`, `tradeType`, `priceText`, `rentText`, `priceMan`, `areaM2`(전용), `supplyAreaM2`, `floor`, `building`, `direction`, `confirmedOn`, `description`, `realtor`를 갖는다. 원문 링크는 검증한 숫자 ID로 화면에서 생성한다.

## 브라우저 방식 후속 작업 (2026-11-06)

사용자가 브라우저 방식으로 실제 매물을 수집해 먼저 보여 달라고 요청했다.

- 브라우저 연결 재확인: `Local browser use is disabled in Work settings`가 계속 반환됐다.
- 설치된 Chrome을 Computer Use로 실행하려는 시도는 자동 승인 검토에서 거절됐다. 사유: 로컬 브라우저 사용이 비활성화된 설정을 다른 경로로 우회하려는 시도이며 그 방식에 대한 구체적인 승인이 없다는 판단. 다른 실행 경로나 간접 실행은 시도하지 않았다.
- 사용자에게 Work 설정에서 로컬 브라우저 사용을 활성화하도록 요청했다. 실제 페이지 접근과 즐겨찾기 읽기, 실제 광고 수집은 활성화 대기 상태다.
- 대기 중 `server/naver-browser-capture.mjs`와 `pnpm listings:import-browser`를 추가했다. 실제 관찰 값을 검증·정규화해 저장하는 도구이며 브라우저를 실행하거나 크롤링하지 않는다. 이 도구만 실행했다고 브라우저 수집 성공으로 간주하지 않는다.
- 브라우저 관찰에는 원문 단지 URL과 관찰 시각을 남긴다. 주소를 대조하고 광고 ID·가격·면적을 검증한다. 일부 광고만 본 결과는 `collectionMethod:'browser'`, `coverage:'partial'`로 저장한다. 이후 API 수집이 실패해도 일부 수집 표시는 유지한다.
- 실행 중인 로컬 API가 새 관찰 스냅샷을 다시 읽으므로 서버 재시작 없이 표시할 수 있다.
- 추가된 저장·HTTP 회귀 테스트 5개와 기존 수집기 17개, 화면 테스트 10개 통과. 테스트의 광고는 모의 자료이며 공개 파일에 저장하지 않았다.
- 후속 `pnpm test:data` 22개, `pnpm build`의 빌드 전후 실거래 343,552건 대조, `pnpm check:publish` 공개 파일 295개 검사가 통과했다. 로컬 화면과 변경 컴포넌트 HTTP 200 및 최신 일부 수집 표시 코드의 응답을 확인했다. Codex 브라우저 패널 열기 요청은 다시 `queued`로 반환됐다.
- **이 단계까지는 실제 브라우저 수집이 실행되지 않았다.** 이후 재접속하여 아래 절의 실제 수집 검증을 수행했다.
