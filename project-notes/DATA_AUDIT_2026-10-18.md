## 결론

현재 수집 범위인 영통구·분당구·수지구의 **2000년 10월~2026년 10월, 939개 구·월**을 국토교통부 API로 전수 재조회했다. 최종 성공 응답은 982페이지, 원천 거래는 **343,552건**이다. 조사 대상 운영 스냅샷은 **343,543건**이다.

두 종류의 문제를 확인했다.

1. **원천과 운영 데이터의 차이:** 운영에 없는 거래 10건(유효 4건·해제 6건), 현재 원천에서 확인되지 않는 운영 거래 1건, 해제 상태가 다른 거래 2건.
2. **단지 조회 연결 문제:** 공개 데이터에 존재하는 **15개 거래명 그룹, 14,557건**이 지도 마스터 단지와 연결되지 않았다. 동별 조회와 실거래명 직접 검색으로는 접근할 수 있지만, 해당 마스터 단지를 선택하면 일부 또는 전체 거래가 나오지 않는다.

조회 조건으로 걸러진 결과나 단순 총건수만 비교하지 않았다. 같은 날짜·금액·면적·층의 계약도 별개일 수 있어 중복을 임의로 제거하지 않고 **동일 행의 개수까지 보존한 다중집합**으로 대조했다.

이번 작업은 조사다. 거래 DB·수집 설정·운영 데이터·화면 코드는 변경하지 않았다. 반복 조사용 스크립트와 비교 모듈·테스트, 보고서만 추가했다. 커밋·푸시는 하지 않았다.

## 원천 차이가 남는 이유

[수집 설정](../automation/config.json#L4)의 `recent_months`가 3이고 [예약 수집](../scripts/automation.mjs#L16)은 실행 시점의 최근 3개 **계약월**만 다시 조회한다. 2026년 10월에는 8·9·10월만 갱신하므로, 5~7월 계약에 뒤늦게 생긴 신고·정정·해제는 계속 이전 상태로 남을 수 있다.

확인된 누락 10건과 원천에서 사라진 기존 1건은 모두 이 재수집 범위 밖에 있다. 7월 벽적골우성의 10월 해제도 같은 문제다. 반면 8월 신나무실진흥은 재수집 범위 안이므로, 최근 운영 수집 시각과 이번 원천 조회 시각 사이의 반영 차이를 추가로 고려해야 한다. 이 1건까지 전부 최근 3개월 정책 때문이라고 단정하지 않았다.

원천 설명은 법정동 앞 5자리와 계약년월로 조회하는 신고 자료이며 업데이트 주기를 실시간으로 명시한다. 따라서 일 단위 수집 시각 이후의 원천 변경은 다음 수집 전까지 차이가 날 수 있다. [공공데이터포털 공식 설명](https://www.data.go.kr/data/15126469/openapi.do).

원천 거래명은 같은데 후보가 여러 개라는 이유로 임의의 한 후보에 거래를 배정하면 다른 오류가 생길 수 있다. 현재 `0건` 안내도 ‘확정된 연결 없음’과 ‘해당 기간 거래 없음’을 구분하지 못한다.

## 누락이 발견되지 않은 구간

- 로컬 보관 원천 응답의 최신 **939개 구·월**: API 총건수·페이지·정규화 결과와 작업 DB가 일치했다.
- 로컬 작업 DB **343,038건 → public JSON → docs JSON**: ID와 거래 필드·해제 정보의 손실 없음.
- 로컬 원천 필드 **343,038건** 재정규화: 현재 정규화 코드 결과와 불일치 없음.
- 운영 공개 JSON **343,543건 → 월별 조회 파일 757개**: 모든 거래의 ID·거래 필드·해제일을 대조했고 누락·추가 없음.
- 로컬·운영 공개 SQLite: 압축/해제 체크섬과 무결성 검사 통과. JSON과 전체 거래 필드, 원천 필드, 도로명주소를 대조해 일치했다. 로컬 public과 docs의 SQLite 바이트도 일치한다.
- 운영 실거래 식별 그룹 **612개 → 검색 결과 594개**: 병합된 단지의 거래 키까지 펼쳐 검사한 결과, 검색 목록에서 빠진 식별 그룹과 중복 소유된 거래 키 없음.
- 법정동·기간만 지정하고 면적 제한 없이 해제 거래를 포함한 조회 함수에서 원본 건수 누락 없음.

수지구 2013년 11월 조회 파일은 첫 접근에서 HTTP 503을 받았으나 재조회에서 HTTP 200으로 복구됐다. 체크섬과 558건 전체가 원본과 일치했다. 지속적인 파일 누락으로 분류하지 않았다.

## 범위상 주의점

- 단지 연결 테이블에는 추가로 `unmatched` 238개 거래명 그룹, 운영 거래 128,938건이 있다. 지도 수집 대상 밖의 동이나 현재 마스터와 연결할 수 없는 과거 거래도 포함할 수 있으므로 이 전체를 오류나 데이터 손실로 분류하지 않았다. 전체 실거래 검색 키에는 포함된다.
- 상세 매매 API도 별도로 대조를 시도했지만 HTTP 403 응답으로 확인하지 못했다. 이번 원천 전수조사의 기준은 앱이 실제 사용하는 일반 매매 API `RTMSDataSvcAptTrade`다. 상세 API와의 동등성까지 검증했다는 뜻은 아니다.
- 개인별 저장 면적·기간·평대·해제 포함 조건, 오래된 즐겨찾기의 거래 키는 실제 개인 브라우저를 읽지 않았다. 기본 조건 및 공개 단지 데이터의 경로를 검증했다.
- 클라우드 비공개 작업 DB를 직접 복호화하지는 않았다. 운영 검증은 공개 SQLite 전체와 공개 JSON·월별 파일을 기준으로 했으며, 로컬 작업 DB는 보관 원천 응답과 직접 대조했다.
- API 조회·비교는 읽기 전용이며 원본 DB를 교체하거나 운영 수집을 실행하지 않았다. 로컬 보고서와 캐시만 생성했다.
