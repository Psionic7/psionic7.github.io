# 관리자 인증 정리 · 2026-10-10

## 분석
사용자는 외부 호스팅 계정 없이 GitHub 로그인만 사용하는 간단한 관리를 요청했다. 기존 OAuth 구현은 별도 서버와 서버 Secret이 필요했으므로 요청에 맞지 않는다. 정적 사이트가 Actions Secrets를 읽어 GitHub API를 호출할 수는 없다.

## 변경 계획
1. 이전에 추가한 Worker, Durable Object 세션, 전용 배포 workflow, 포털 빌드, 서버 세션 클라이언트와 관련 테스트·설정·설명서를 제거한다.
2. 서버 도입 전의 관리 화면과 GitHub API 클라이언트를 복원하여 기존 지역 지도·설정 저장·수집 작업을 보존한다.
3. 사용자의 최종 요청에 따라 GitHub 토큰으로 접속하는 기존 지도형 관리자 구조를 복원한다. 별도 GitHub OAuth 로그인이나 GitHub 관리 화면으로의 전환은 적용하지 않는다.
4. 토큰 및 API 키의 저장 위치를 구분해서 안내하고, 테스트·빌드·게시 파일 검사를 수행한다.

## 제거 결과
- auth-admin 서버 폴더, 전용 배포 workflow, 포털 Vite 설정·빌드 명령, 세션 클라이언트와 인증 테스트를 제거했다.
- 공개 사이트 빌드에서 ADMIN_PORTAL_URL 연결과 인증 모드 플래그를 제거했다.
- 전용 서버 배포용 환경변수·Secrets는 등록한 적이 없고 외부 서버도 배포한 적이 없다. 기존 수집용 Secrets는 유지한다.
- 모의 로그인 미리보기 서버를 종료했다. 서버 시뮬레이션이나 OAuth 로그인 화면을 실제 로그인처럼 제공하지 않는다.

## 토큰과 키 보관
- GitHub Actions는 실행마다 자동 GITHUB_TOKEN을 제공한다. GitHub 화면에서 수동 수집을 시작할 때 사용자가 별도 관리자 토큰을 입력하거나 등록할 필요가 없다.
- MOLIT_SERVICE_KEY, JUSO_ADDRESS_SEARCH_KEY, COLLECTION_STATE_KEY는 기존 저장소 Settings → Secrets and variables → Actions의 Secrets에서 관리한다.
- 기존 사이트 안에서 지도로 설정을 저장하는 토큰 방식은 현재 페이지의 GitHub 토큰 입력란을 사용한다. 토큰은 메모리에만 있고 새로고침·로그아웃하면 제거된다. Actions Secrets에 넣어도 공개 사이트가 그 값을 읽을 수 없다.
- 코드·URL·localStorage·sessionStorage·공개 변수에 토큰을 넣지 않는다.

## 현재 상태
사용자가 기존 구조 복원을 최종 요청했다. Cloudflare 기반 구현은 제거하고 GitHub 토큰으로 접속하는 기존 관리자 화면·GitHub API 클라이언트·지도·설정 저장·수집 실행·실행 기록을 복원했다. 기본 수집 시간은 매일 한국 시간 01:00을 유지한다. 복원 후 사용자가 현재 변경의 커밋·푸시를 명시적으로 요청했으므로 기존 관리자 구조 복원과 관련 문서를 함께 main에 반영한다.

## 검증
복원 후 React 14개 파일, 84개 테스트, 공개 빌드, 게시 파일 검사(206개), git diff --check가 통과했다. 실제 사용 코드·워크플로·빌드 설정·설명서에서 외부 인증 서버 설정이 남지 않았음을 검색으로 확인했다. 기존 4173 미리보기 서버의 /admin.html이 HTTP 200이며 복원한 최신 관리자 스크립트를 제공하는지 확인하고 Codex 브라우저 패널에 열었다.

## 요약
기존 지도형 관리자 구조로 복원 완료했다. 관리자 토큰은 기존 입력란에 넣고 페이지 메모리에서만 사용한다. 수집용 API 키와 암호화 키는 기존 Actions Secrets에 유지하며, 실제 데이터 수집·배포는 GitHub Actions가 수행한다.

최종 복원 확인: 소스·워크플로·빌드 결과 10개 파일이 인증 변경 전 3fcc252와 일치한다. 실제 390px 모바일 브라우저에서 토큰 입력란 1개, OAuth 서버 링크 0개, 가로 넘침 없음, JavaScript 오류 없음과 지역 목록 로드 후 접속 버튼 활성화를 확인했다.
