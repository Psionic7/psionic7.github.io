# 주거 지도 표시 및 입구 아이콘 수정 — 2026-10-09

## 원인과 해결

수지광교산아이파크의 공식 대장 용도는 노유자시설(노인복지주택)이었다. 기존 아파트 전용 분류에서는 other로 남아 공개 지도에서 제외됐다. 명시적으로 노인복지주택인 주건축물만 senior_housing으로 분류하고, 기존 아파트와 함께 지도 마스터에 포함했다. 일반 요양시설과 부속 시설은 제외한다. 같은 조건에 해당하는 금곡동 더 헤리티지도 함께 반영됐다.

기존 inventory 테이블의 CHECK 제약을 트랜잭션으로 확장했다. 행·원천 JSON·ID는 그대로 복사하며 기존 DB에도 적용된다. 캐시를 재구성할 때 새 유형만 재판정하고, 층별 용도로 이미 확인된 복합건물 아파트의 분류는 보존한다.

아이파크 총괄표제부의 hhldCnt는 0, hoCnt는 559였다. 총괄 호수에는 상가 등도 포함되므로 559를 주거 수로 사용하지 않는다. 노인복지주택으로 확인한 주거동 표제부 hoCnt를 합산한 537호를 팝업에 표시한다. 원천 세대수 필드는 변경하지 않는다.

삼성 쉐르빌은 서로 다른 공식 ID 5개가 같은 좌표에 있어 아이콘이 겹쳤다. 좌표가 정확히 같은 항목만 한 입구 핀에 묶고, 숫자 배지와 팝업 선택 메뉴로 모두 접근하도록 했다. 가까운 다른 좌표를 임의로 병합하지 않는다. 실제 거래가 연결된 ID hub:11161184256을 첫 항목으로 보여준다. 공식 레코드·필지·ID·즐겨찾기와 거래 연결은 유지된다.

입구 핀은 글자 기호에서 SVG 건물 그림으로 변경했다. 청록 그라데이션, 흰 테두리, 그림자와 핀 형태를 사용하며 즐겨찾기는 금색으로 표시한다. 키보드 Enter로 팝업을 열고 포커스 테두리도 표시한다.

## 입구 아이콘 상호작용 오류 수정

빠른 연속 클릭이 Leaflet의 지도 더블 클릭 확대에도 전달됐다. 팝업 크기에 맞춰 이동한 뒤 확대가 진행되면 팝업이 지도 위쪽으로 벗어났고, 닫기 버튼이 지도 외부의 안내 카드에 가려 클릭되지 않았다. 실제 브라우저에서 지도 상단 370px보다 팝업 상단이 283px로 벗어나는 사례를 기록했다.

입구의 dblclick 이벤트 전파/기본 동작을 막았다. 이미 열린 같은 입구는 팝업을 다시 만들지 않아 선택 항목도 유지한다. 지도 moveend/zoomend 이후 팝업 위치를 재검사하며, 크기가 바뀌지 않은 이동에서는 콘텐츠를 다시 붙이지 않아 입력 포커스를 보존한다. 크기 변경 시에도 기존 포커스를 복원한다.

팝업이 작은 지도 폭을 거의 채우면 여백을 줄이고, 반 픽셀 이하의 차이는 이동시키지 않는다. 이동량은 실제 넘침을 해소하는 방향으로 반올림해 영 픽셀 이동 이벤트나 좌우 왕복 보정을 방지했다. 팝업을 닫으면 이동/확대 이벤트와 예약 프레임도 정리한다.

검증: Node 79개 + React 63개 = 142개 통과. 실제 브라우저에서 연속 클릭, 배지 클릭, 지도 상단 가장자리 클릭, 항목 선택 후 팝업이 지도 안에 있음을 확인했다. 기존 아이파크·삼성·즐겨찾기·키보드·모바일 브라우저 검증과 공개 파일 검사도 통과했다. 진단 로그/화면은 local/icon-*.json, local/icon-*.log, local/icon-*.png에 저장했다.

## 사용자 요청에 따른 아이콘 원복 (현재 상태)

앞선 클릭 보정 후에도 사용자가 클릭 시 다른 위치로 이동하는 현상을 보고하여 새 아이콘을 원복했다. 위 아이콘 구현·상호작용 수정 기록은 작업 이력이며, 현재 코드에는 적용되지 않는다.

ApartmentMapCanvas.jsx와 apartment-map.css는 아이콘 변경 전 HEAD의 내용으로 복원했다. 기존 20×20 ▥ 아이콘·10×10 기준점·개별 단지 클릭·기존 팝업 처리로 돌아갔다. SVG 핀, 숫자 배지, 동일 입구 묶음, 추가 클릭/확대 처리와 추가 위치 보정 모듈 및 전용 테스트는 제거했다. 화면 안내와 README도 현재 동작에 맞췄다. 기존 팝업이 화면 안에 들어오도록 지도 이동을 하는 원래 동작은 유지된다.

아이파크/더 헤리티지의 노인복지주택 분류와 지도 반영(467개), 아이파크 주거 537호, 건물 하단의 지상·지하 층수만 표시는 유지했다. 삼성 쉐르빌 공식 항목 5개는 원래처럼 개별 위치 아이콘을 사용하며, 공식 좌표가 같아 아이콘이 겹칠 수 있다.

원복 검증: Node 76개 + React 61개 = 총 137개 통과. pnpm build, pnpm check:publish(170개 공개 파일), git diff --check 통과. 지도 코드와 CSS가 원래 HEAD와 바이트 단위로 동일함을 확인했다. 실제 브라우저에서 기존 ▥/20×20 표시, SVG·배지 제거, 아이파크 주거 정보, 즐겨찾기, 닫기 후 재클릭, 삼성 개별 아이콘 5개, 모바일 390px을 확인했다. 팝업 끝과 클릭 아이콘의 수평 차이는 0px, 수직 차이는 약 3.5px로 같은 위치에 연결됐으며 pageerror는 없었다. 건물 하단 추가 목록은 지상·지하 층수 두 항목만 남아 있음을 확인했다. 결과/화면은 local/icon-revert-browser-result.json, local/icon-revert-desktop.png, local/icon-revert-mobile.png에 저장했다. 커밋·푸시는 수행하지 않았다.

## 후속 커밋·푸시 요청

사용자가 현재 작업에 대해 커밋과 푸시를 명시적으로 요청했다. 위 미커밋 상태 기록은 요청 이전의 작업 이력이다. 노인복지주택 지도 반영, 건물 하단 층수 정보 간소화, 기존 아이콘 복원 상태와 공개 빌드·테스트·문서를 커밋 대상으로 포함한다. 비공개 local/ DB·백업·화면 진단 파일은 제외한다. 마지막 검증 이후 구현 코드 변경은 없다.
