# 추가 버그 점검: 공식 단지 연결과 배포

점검일: 2026-11-14. 공식 단지 연결 누락과 승인 충돌 검사 오류의 원인·수정·검증 결과를 기록한다. 아래 운영 상태는 점검 당시 기준이며 배포 완료를 의미하지 않는다.

## 1. 분당지웰푸르지오의 승인 연결 누락으로 배포 중단

직전 커밋 `784ef04`의 [배포 실행 43551930452](https://github.com/Psionic7/psionic7.github.io/actions/runs/43551930452)은 `Check official apartment ID query coverage`에서 실패했다. 검사 결과는 공식 ID 보강 거래 60,773건 중 다음 2건의 기존 조회 누락이었다.

이전 승인 연결은 당시 공개 관측과 로컬 자료로 확인한 593개 공식 단지였다. 최신 클라우드 DB에는 추가 과거 월의 상세 API 관측이 있었고, 이 단지의 공식 번호가 기존 승인 목록에 없었다. 상세 API의 가격 오류가 아니라 승인 연결의 누락이다. 검사에서 게시를 중단했으므로 새 기준본은 운영에 반영되지 않았다.

상세 API의 분당구 2025년 6월 응답을 다시 받아 해당 번호의 두 계약을 확인했다. 계약일·금액·면적·층·준공연도·주소 등 정규화된 11개 필드가 로컬 원본과 모두 일치했다. 이름 유사도로 연결하지 않았다.

DB 복사본에서 먼저 승인 연결을 추가하고, 상세 관측을 적용한 검증 DB에서 누락 2건 → 0건을 확인했다. 이후 로컬 원본 `apartment_molit_sources`에 같은 계약 근거로 확정해 승인 연결을 594개로 늘리고 공식 기준본 생성 명령을 실행했다.

- 새 기준본: `ceac112e55f512af1cd96d0ed4cd04e45cc2d95e6f537a66cbde73d9fd812339`
- 원본 DB의 거래 344,537건과 거래·수집 이력·아파트 대장·네이버 확정 연결 등 기존 15개 테이블의 행 수와 전체 해시가 변경 전후 일치했다.
- 로컬 원본에 동결 기준본을 설치하지 않았다. 최신 클라우드 전체 DB를 로컬 DB로 교체하지 않았다.
- 이번 누락을 해결한 것이며 향후 새로운 공식 번호의 자동 승인을 허용한 것은 아니다. 다음 미확정 번호도 로컬 검토 후 기준본에 반영해야 한다.

## 2. 다음 검토 묶음에서 기존 공식 ID의 다른 원천이 승인되는 버그

`planMolitSourceConnections`는 관측 묶음 안의 공급자→원천 충돌과 기존 원천→공급자 충돌은 검사했지만, 기존 승인에 있는 공급자→원천 관계를 새 관측의 충돌 검사에 포함하지 않았다.

예를 들어 첫 검토에서 공식 ID A를 지번 693의 원천에 승인한 뒤, 다음 검토에 같은 A와 지번 694의 계약만 전달하면 기존 원천이 후보 집합에서 빠졌다. 새 주소에도 로컬 계약이 있으면 동일 공급자에 두 번째 원천을 추가할 수 있었다. 명시적인 복수 범위 승인과 구분되지 않는 오류다.

기존 승인 원천도 해당 공급자의 후보 집합에 포함하도록 수정했다. 기존 승인과 다른 원천이 관측되면 `ambiguous_source`로 보류하고 기존 연결은 보존한다. 승인된 복수 범위 자체를 삭제하거나 실행 중에 재배정하지 않는다.

`tests/molit-source-connections.test.mjs`에 두 번의 분리된 검토를 재현하는 테스트를 추가했다. 수정 전에는 새 연결 1개가 생성돼 실패했고, 수정 후에는 새 연결 0개·보류 1개가 되며 저장된 승인 연결도 그대로다.
