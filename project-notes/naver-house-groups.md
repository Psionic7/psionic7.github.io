# 네이버 동일 주택 광고 묶음

기존 수집은 개별 광고와 동일주소 광고 수만 보존했다. 이 수치만으로는 광고 간 관계를 알 수 없어 주택으로 병합하지 않았다.

수집기는 일반 매매 광고 전체 페이지를 확인한 뒤 네이버의 동일매물 묶기를 켠다. 묶음 목록의 각 대표 광고를 페이지별로 펼쳐 실제 하위 광고번호를 수집한다. 대표 버튼은 펼치면 `data-nclk` 값이 바뀌므로 이 값으로 순회 대상을 다시 고르지 않는다.

`providerHouseId`는 `네이버단지번호:대표광고번호`다. 해당 단지 묶음 목록에서 관측한 대표 광고의 실제 하위 응답만 인정한다. 서로 다른 대표가 같은 광고를 포함하면 수집을 실패 처리해 이전 자료를 보존한다. 일반 목록에 없지만 묶음 안에서 실제 관측된 활성 매매 광고도 저장한다.

화면은 한 묶음당 대표 행 한 개와 호가 범위를 보여준다. 아래 펼치기에는 중개사별 광고·가격·확인일·원문을 모두 표시한다. 페이지는 광고가 아닌 대표 행 단위로 나눈다. 네이버 관계가 없는 과거 광고나 수집 제한 시간 내 확인하지 못한 광고는 `묶음 미확인`으로 따로 남긴다. 층·면적·가격이 같거나 동일주소 광고 수가 같다는 이유로 합치지 않는다. 표시된 묶음 수는 네이버의 분류 기준이며 독립적인 호수 확인 결과가 아니다.

일일 자동 수집은 같은 수집기를 사용하므로 이후 수집부터 관계가 저장된다. 기존 모든 단지에 관계가 있다고 추정해 채우지는 않는다. 실제 확인 예시는 동천센트럴자이 스냅샷에 반영한다.

2026-11-09 실제 Chrome 관측에서 동천센트럴자이 활성 매매 광고 189개를 네이버 묶음 38개로 연결했다. 묶음 미확인 광고는 0개였다. 같은 세션에서 일반 목록 전체와 묶음 목록 2개 페이지, 대표별 하위 응답을 대조했다. 광고 수는 수집 시점에 따라 변한다.

검사: `tests/listing-houses.test.mjs`에서 중복 광고번호, 다른 단지·다른 대표의 분리, 유사 필드만으로 병합 금지, 하위 목록에서만 노출된 광고 보존, 상충하는 관계 거부를 확인한다. `tests/apartment-sale-listings.test.jsx`에서 대표 행과 중개사별 하위 목록·가격·원문을 확인한다.
