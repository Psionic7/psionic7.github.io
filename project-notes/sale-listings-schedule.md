# 매매 매물 전용 일일 수집

후속 무인 수집 작업에서 기본 소스를 시스템 Chrome으로 전환하고, 실제 네이버의 매매 전체 페이지 및 자동 검색 검증을 추가했다. 현재 운영 경로는 [시스템 Chrome 무인 수집 문서](unattended-naver-listings.md)를 확인한다. 아래 접속 실패 기록은 전환 이전 Playwright 환경의 기록이다.

## 요청과 변경

매물 수집 범위를 아파트 매매(`APT`, `A1`)로 제한하고 실거래가 수집과 함께 매일 실행한다.

1. 직접 요청, Playwright, 시스템 Chrome, 수동 브라우저 가져오기 경로를 매매 전용으로 바꾼다.
2. 저장한 수집 지역 전체의 활성 아파트를 기존 실거래가 작업에서 이어서 수집한다.
3. 한국 날짜별 단지 시도 기록과 실패 시 이전 매매 광고 보존을 검증한다.
4. 기존 공개 스냅샷과 지역 보고서에서 임대 광고를 제외하고 화면·빌드를 확인한다.

## 예약 실행

- 기존 `.github/workflows/refresh-data.yml`의 일일 cron `0 16 * * *`는 한국 시간 다음 날 01:00이다. `automation/config.json`의 `time_kst`와 일치한다.
- 같은 작업의 `scripts/automation.mjs collect`가 실거래가 → 도로명주소 → 매매 매물 순서로 실행한다. 별도의 중복 cron은 추가하지 않는다.
- 대상은 즐겨찾기가 아니라 저장된 기본 수집 지역 전체의 활성 아파트다. 수지 외 기본 수집 지역도 포함한다.
- `A1`로 표시한 당일 실행만 재사용한다. 이전의 전체 거래 유형 실행 기록 때문에 매매 수집을 생략하지 않는다.
- 최초 시도는 한국 날짜별 하루 한 번이다. 같은 날 다시 실행하면 이미 시도한 단지는 건너뛰며, 명시적인 `--force`로만 다시 시도한다.
- 광고 실패·단지 연결 미확정·미시도는 0건 성공과 구분한다. 마지막 페이지까지 검증해야 전체 성공이며 일부 수집을 성공으로 올리지 않는다.

## 매매 범위와 기존 자료

- 직접 요청은 `tradeType=A1`을 사용한다. 브라우저는 `a=APT&b=A1&e=RETAIL`로 탐색한다.
- 브라우저 목록 증거는 실제 요청의 `realEstateType=APT`, `tradeType=A1`, `sameAddressGroup=false`를 확인한다. 전체 거래·전세·월세 목록으로 매매 전체 수집을 완료 처리하지 않는다.
- 응답에 임대 광고가 섞이면 제외한다. 매매 전용으로 표시한 스냅샷에 임대 광고가 있으면 저장 검증에 실패한다.
- 수동 일부 가져오기에 매매 광고가 없으면 실패한다. 임대 광고만 있는 일부 목록을 매매 0건으로 저장하지 않는다.
- `node scripts/filter-sale-listings.mjs`는 기존 공개 자료의 매매 광고만 유지하고 지역 보고서를 다시 검증한다. 관찰 시각과 전체·일부 구분을 바꾸지 않으며 새 수집으로 기록하지 않는다.
- 수지는 48개 네이버 단지, 매매 광고 681건이다. 등록 대상 199개 중 연결 미확정·주소 불일치 150개는 그대로다. 기존 분당 자료를 합한 전체 공개 매매 광고는 694건이다.
- 새 일일 스냅샷으로 과거 지역 보고서의 관찰 정보가 더 이상 일치하지 않으면 해당 보고서를 제거한다. 과거 보고서 때문에 이후 예약 내보내기가 막히지 않게 한다.

## 검증 범위와 운영 상태

실제 Chromium을 사용한 로컬 서비스 테스트로 검색 → 매매 조건 탐색 → 목록 스크롤 → 마지막 페이지 대조를 검증한다. 기본 지역 대상 선정, 당일 중복 방지, 다음 한국 날짜 재수집, 암호화 DB 복원, 전세·월세 제외, 과거 기록 전환을 함께 확인한다.

현재 기본 무인 Playwright 환경의 실제 네이버 접속은 이전에 404 안내 화면으로 실패했다. 이번 작업은 접근 제한을 해결한 것으로 보고하지 않으며 실제 원격 일일 수집 성공을 주장하지 않는다. 실패하면 미완료 상태와 이전 매매 자료를 유지한다.

구현·검증 후 사용자의 별도 커밋·푸시 요청에 따라 변경을 `main`에 반영한다. 원격 일일 수집의 수동 실행은 수행하지 않는다. 푸시 후 배포와 다음 예약 실행에서 매매 전용 변경을 사용한다.

검증 결과:

- `pnpm test:node`: 170개 통과, `pnpm test`: 134개 통과.
- `pnpm test:listings`: 실제 Chromium 동작을 포함한 56개 통과, `pnpm test:data`: 22개 통과.
- `pnpm build`, `pnpm data:verify`, `pnpm check:publish` 통과. 빌드 전후 실거래 343,552건·757개 월별 파일·939개 구·월 원천 이력 대조 통과.
- 읽기 전용 `listings:daily --plan`: 한국 시간 01:00·매매(`A1`)·21개 동·활성 아파트 467개 확인.
- 공개 스냅샷의 모든 광고가 매매임을 확인했고, 지역 보고서 집계와 public/docs 스냅샷의 일치를 확인했다.
- 인앱 브라우저의 수지 결과 화면에서 48개 단지·매매 광고 681건, 매매가 정렬, 전용면적 필터와 일일 매매 수집 안내를 확인했다. 미리보기는 <http://127.0.0.1:5173/naver-listings-preview.html?region=41465>에서 열 수 있다.
