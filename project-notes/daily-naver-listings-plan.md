# 지역 전체 아파트 매물 일일 수집

작성: 2026-11-06. 요청: 기본 수집 지역의 모든 아파트를 하루 한 번, 실거래가 수집과 함께 수집한다.

## 범위와 실행

- 대상은 개인 즐겨찾기가 아닌 `automation/config.json`의 저장 지역이다. 현재 21개 동, 로컬 건축물대장 마스터의 활성 단지 467개를 확인했다. 이름 미확정 7개도 대상에서 삭제하지 않는다. 마스터의 지역 목록 스캔 완료와 부가 정보 완성도는 구분한다.
- 기존 일일 예약(한국 시간 01:00)과 웹 관리자의 수동 실거래 수집이 같은 매물 작업을 호출한다. 코드 푸시에 의한 재배포는 재수집하지 않는다.
- 한국 날짜별 실행 기록과 단지별 시도 결과를 작업 SQLite에 남긴다. 같은 날짜의 재실행은 완료한 시도를 반복하지 않는다. 날짜가 바뀌면 전체 대상을 다시 시도한다. 명시적 강제 재시도 명령을 별도로 제공한다.
- Playwright Chromium을 작업 코드의 의존성으로 설치하고 GitHub Actions에서도 브라우저 화면을 읽는다. 사용자 브라우저 프로필·로그인 세션·인앱 브라우저에 의존하지 않는다. 직접 API 요청이 429였다는 기존 한계는 브라우저 실행 환경에서도 검증이 필요하다.

## 단지 연결과 완전성

- 최초 연결은 아파트명·주소로 네이버 화면에서 검색하고, 단지 정보의 지역·법정동·지번 또는 공식 도로명주소가 일치하는지 확인한다. 네이버 단지 번호를 DB에 보관하고 다음 날 재검증한다. 동명 단지를 이름만으로 연결하지 않는다.
- 아파트 매매·전세·월세만 대상으로 삼고 동일매물 묶기를 해제한다. 실제 목록 광고를 끝까지 불러온 뒤 각 상세 화면에서 광고 번호·금액·정확한 면적을 읽는다. 목록 수와 끝 도달을 검증하지 못한 결과는 전체 수집 성공으로 저장하지 않는다.
- 확인된 0건과 검색 실패·단지 연결 미확정·시간 초과·네이버 차단을 구분한다. 제한·로그인·CAPTCHA 화면은 중단하고 다른 경로나 프록시로 우회하지 않는다.
- 일일 실행에 시간·페이지 상한과 요청 간격을 둔다. 한도 때문에 남은 단지는 미시도로 표시한다. 대상 전체 성공 여부와 각 결과를 공개 상태에 표시한다.

## 저장·배포·화면

- 연결, 마지막 성공 스냅샷, 일일 실행 상태는 작업 DB에 저장해 기존 암호화 DB 보관·복원에 함께 포함한다. 브라우저 프로필과 인증 값은 저장하지 않는다.
- 실패한 단지의 마지막 성공 자료를 보존한다. 매물의 외부 연결 실패가 정상 실거래 추출·배포를 막지 않도록 부분 실패를 기록하며, 매물 전체 성공으로 표시하지 않는다. 형식 오류·DB 저장 실패는 숨기지 않고 실패시킨다.
- 공식 자동화 내보내기에서 검증한 매물 스냅샷을 `public/listings/snapshot.json`으로 출력한다. 기존 실거래는 계속 `exportData`를 통해 검증·추출한다.
- 공개 사이트는 즐겨찾기와 일치하는 단지의 저장 매물을 조회한다. 기존 실거래 기반 즐겨찾기와 마스터 기반 단지를 검증된 거래 별칭으로 연결한다. 일일 작업의 지역·대상·성공·실패·미시도 수와 시각을 표시한다.

## 검증과 인수 조건

- 지역 범위·이름 미확정 포함·다른 지역 제외, KST 날짜 경계·중복 방지·다음 날 재수집, 실패 후 이전 자료 보존을 검증한다.
- 실제 브라우저 코드로 로컬 네이버 형태의 테스트 페이지를 탐색해 검색 → 주소 확인 → 목록 스크롤 → 상세 → 전체 저장을 검증한다. 네이버 실제 페이지의 스모크 검증은 별도로 기록한다.
- 자동화의 실거래 → 주소 → 매물 순서와 재배포 시 무수집, DB 복원 후 상태 유지, 누락·잘못된 응답을 검사한다.
- `pnpm test:data`, 관련 Node·React 테스트, 빌드 전후 데이터 검사, 공개 파일 검사를 실행한다. 화면을 변경하면 로컬 미리보기를 브라우저에서 확인한다.
- 커밋·푸시·원격 워크플로 실행·배포는 이 요청에서 수행하지 않는다. 실제 예약 반영은 변경 코드가 배포된 뒤 가능하다.

## 구현 결과

- `server/daily-naver-listings.mjs`가 저장 지역의 활성 아파트를 계획하고 일일 실행을 관리한다. `--plan`의 읽기 전용 조회로 **21개 동·467개 단지·이름 미확정 7개**를 재확인했다. 지도 좌표나 실거래가 없는 단지를 제외하지 않는다. 같은 동에 공식 이름이 중복되면 검증된 실거래 별칭을 검색어로 우선 사용한다.
- `naver_listing_connections`, `naver_listing_snapshots`, `naver_listing_days`를 작업 DB에 저장한다. 날짜는 한국 시간으로 계산한다. 당일 추가 단지만 새로 시도하고, 목록에서 빠진 단지는 집계에서도 제거한다. 마지막 단지 직후 중단된 실행도 재수집 없이 마무리한다. `--force`로 명시적으로 재시도할 수 있다.
- `server/naver-browser-collector.mjs`는 별도 Chromium으로 홈페이지 검색과 주소 검증, 목록 스크롤을 수행하고 브라우저가 받은 응답을 읽는다. 마지막 페이지·연속 페이지 번호·중복 광고 번호·단지 주소를 검사한다. 브라우저 화면용 요청을 프로그램에서 직접 재현하거나 인증 값을 수집하지 않는다. 전체 수집과 이전의 4건 일부 수집을 별도로 표시한다.
- 기존 `collectConfigured`는 **실거래 → 도로명주소 → 지역 전체 매물** 순서로 실행한다. 로컬 관리자의 실거래 수집도 같은 일일 함수를 호출하며 중단 신호를 전달한다. 연결 실패는 이전 매물을 유지하고 실패·미확정·미시도를 구분한다. 내부 형식·DB 저장 오류는 예외를 숨기지 않는다.
- Actions의 기존 일일 예약과 수집을 켠 수동 실행에 Chromium 설치·브라우저 회귀 검사·매물 실행을 추가했다. 코드 푸시나 수집을 끈 재배포에서는 매물 수집을 실행하지 않는다. 준비 작업은 최대 360분, 매물 작업은 최대 3시간으로 제한한다. 각 단지는 기본 120초, 목록 스크롤 사이 기본 1.5초 간격이다.
- 내보내기는 기존 `exportData`를 유지하고, 검증한 매물 JSON과 일일 상태를 함께 출력한다. 작업 DB가 암호화·복원될 때 새 매물 테이블도 유지되는지 실제 SQLite 백업·암복호화 테스트로 확인했다. 공개 DB에는 새 비공개 테이블을 넣지 않는다.
- 대시보드에는 지역 전체의 대상·성공·실패·단지 연결 미확정·미시도 수가 표시된다. 구분 가능한 실거래 별칭으로 기존 즐겨찾기를 마스터 단지의 매물에 연결한다. 이름·지번이 같다는 이유로 여러 후보 중 하나를 임의로 선택하지 않는다.

## 검증과 실제 접속의 한계

- `pnpm test:listings`: 일일 상태·수집·암호화 복원·실제 Chromium의 로컬 테스트 페이지 동작 검사 **40개 통과**. 404 진입을 빈 매물 성공으로 저장하지 않는 회귀도 포함한다.
- 기존 전체 Node 테스트 150개와 전체 React 테스트 132개 통과. 이후 추가한 일일 재개·대상 제거·취소·암호화 복원, 로컬 관리자 호출 및 화면 상태 테스트도 관련 명령으로 통과했다.
- 최종 매물 화면 테스트 12개, 로컬 관리자·일일 수집·Chromium 검사 32개 통과. 모의 네이버 응답은 테스트용 로컬 서버에서만 제공했고 실제 공개 매물로 저장하지 않았다.
- `pnpm test:data` 22개 통과. `pnpm build`에서 실거래 **343,552건**, 월별 조회 파일 757개, 저장된 원천 939개 구·월의 빌드 전후 검증 통과. 실거래 원본은 재수집하거나 변경하지 않았다.
- `pnpm check:publish`: 공개 파일 **310개** 검사 통과. 매물 스냅샷·일일 상태 형식, 두 상태의 일치와 `public`/`docs`의 동일성을 검사한다.
- 기존 pnpm 저장소와 설치 상태가 달라 명령 실행 전 검사에 실패했으나, 고정 잠금 파일로 의존성을 다시 확인한 뒤 `pnpm test:data`와 `pnpm build`를 정상 실행했다. 새 의존성은 Playwright 1.65.0이다.
- <http://127.0.0.1:5173/?tab=dashboard>와 로컬 웹 관리자를 실제 인앱 브라우저로 확인했다. 일일 작업 미실행 상태를 사실대로 표시하며, 이전 실제 4건은 일부 수집으로 유지된다. 화면 증거: 비공개 `local/daily-listing-dashboard.jpg`.

**무인 수집의 실제 서비스 접속은 해결되지 않았다.** 같은 네이버 단지 주소를 새 Chromium의 headless·일반 모드로 열면 404 화면으로 이동했다. 네이버가 제공한 공식 새 화면 연결(`fin.land.naver.com/map/redirect?complexId=2663`)도 새 Chromium에서는 404 안내 페이지로 이동했다. 인앱 브라우저에서 읽었던 4건을 이 별도 실행 환경의 성공 증거로 사용하지 않았다. 로그인·CAPTCHA·사용자 브라우저 프로필 복사·우회 프록시는 사용하지 않았다.

접속 확인용 도구와 증거는 `local/check-daily-listing-browser.mjs`, `local/check-naver-browser-entry.mjs`, `local/check-naver-current-service.mjs` 및 대응 JSON에 남겼다. 이 검사들은 원본 작업 DB를 읽기 전용으로 조회했다. 지역 전체의 실제 일일 수집을 실행하거나 성공한 것으로 기록하지 않았다. 공개 일일 상태는 `null`, 기존 실제 일부 광고는 4건이다.

현재 변경은 커밋·푸시하지 않은 로컬 코드다. 원격 예약은 아직 기존 코드로 실행되며, 변경을 반영하더라도 네이버 자동 접속 문제가 해결되기 전에는 매물 작업이 미완료 상태로 기록될 수 있다.

## 2026-11-07 후속 수집

수지 5개 동의 등록 대상 199개를 확인하고, 단지명·지번 검증을 통과한 네이버 48개 단지의 광고 809건을 반영했다. 일부 수집을 포함한 별도 지역 수집이며, 예약 작업 전체 수집 성공으로 기록하지 않았다. 현재 결과와 검증·반영 범위는 [수지 수집 기록](suji-listings-collection.md)을 확인한다.
