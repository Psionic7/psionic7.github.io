# 공식 실거래 단지 ID와 거래 행 보존

## 구현 범위

운영 월 수집은 상세 API의 `aptSeq`를 원문 문자열로 저장한다. 기존 `trades`는 현재 조회 행이며, 기존 즐겨찾기·공유 URL·주거 배정이 참조하는 정수 거래 ID를 유지한다. 로컬 아파트·네이버 승인 연결과 공급자의 수집 관측은 각각의 저장 영역에서 관리한다.

## 현재 수집 흐름

`server/collector.mjs`의 `collectMonth`는 지역·월 응답 전체를 받은 후 트랜잭션으로 저장하고 XML과 DB의 다중집합을 검증한다. `scripts/automation.mjs`와 로컬 관리자 서버가 이 함수를 호출한다. `exportData`는 현재 `trades`와 원천 수집 이력을 확인해 공개 SQLite·JSON·검색·지도를 만든다. 기존 `verifyCollectedMonth`는 과거 실행도 현재 거래와 비교하며, 월별 삭제·재삽입은 행 ID를 바꿀 수 있다.

## 설계 비교와 선택

| 기준 | 현재 거래와 불변 원문 이력 | 모든 관측을 이벤트로 저장하고 현재 조회를 재구성 |
| --- | --- | --- |
| 기존 조회·URL 호환 | 현재 조회 스키마와 내부 참조 유지 | 조회·검증·내보내기 전반의 변경 필요 |
| 중복·정정·취소 | 행별 원문 버전과 월별 소속으로 보존 | 관측마다 보존하며 별도 동일성 판정 필요 |
| ID 재사용 방지 | 독립적인 영구 할당 원장 | 독립적인 영구 할당 원장 |
| 과거 기본 API | 과거 원문과 ID 미확정 상태 수용 | 과거 원문을 이벤트로 이관 |

현재 거래와 불변 원문 이력을 선택한다. 두 읽기 전용 설계 검토가 이 방향에 합의했다. 이벤트 설계에서 월별 현재 원천 참조와 영구 ID 할당을 가져온다. 사용 가능한 실행 모델로 두 설계를 검토했으며 다른 모델 계열의 별도 심사는 실행하지 않았다.

## 저장 책임과 함수 경계

`server/molit-trade-storage.mjs`는 거래의 다중집합 대조, ID 할당, 불변 원문 버전, 실행별 소속과 공식 공급자 단지를 관리한다. `collector.mjs`는 API 요청·페이지 완전성·정규화와 트랜잭션의 최종 검증을 관리한다.

```js
fetchMolitMonth(key, code, month, {service: 'detailed', signal})
storeMolitTradeSnapshot(db, rows, {code, month, runId, previousRunId, service, observedAt})
readMolitRunRows(db, runId)
```

| 저장 영역 | 역할 |
| --- | --- |
| `trades` | 현재 월별 조회 행과 기존 정수 ID |
| `molit_trade_id_ledger` | 한 번 발급한 ID를 보관하는 영구 원장 |
| `molit_trade_revisions` | 거래 ID별 정규화 값과 원문 버전 |
| `molit_trade_runs`, `molit_trade_run_rows` | 실행별 원문 버전과 거래의 다중집합 |
| `molit_trade_heads` | 검증 완료한 현재 월의 실행 |
| `molit_apartments` | 관측된 공식 `aptSeq`와 해당 공급자 단지의 출처 |
| `molit_trade_identities` 뷰 | 현재 거래 ID와 공식 공급자 단지 ID의 연결 |

기본 API 과거 원문에는 공식 ID가 없을 수 있다. 공개 거래의 기존 정규화 열과 내부 ID를 유지하고 상세 원문에 공식 ID를 보존한다. 공식 ID 관측은 로컬 아파트 승인 연결의 변경 권한을 부여하지 않는다.

## 행 동일성 판정

전체 공통 거래 필드가 같은 행부터 중복 개수만큼 대응한다. 기존·신규 양쪽에 공식 ID가 있으면 같은 번호여야 한다. 건물 동·등기일과 공식 ID의 결측 보강은 나머지 공통 필드가 같고 대응이 유일할 때만 기존 ID에 반영한다. 원문 버전은 갱신 전후 모두 보관한다. 가격·계약·취소 상태 변화나 모호한 대응은 새 행으로 보존한다.

응답에서 빠진 거래는 현재 조회에서 제외하고 원문 버전과 발급 ID를 보관한다. 신규 ID는 영구 원장으로 할당하며, 이력 정리 뒤에도 원장과 최고 발급값을 유지한다. 원장 유실을 감지하면 수집을 중단한다. 외부에 공개한 ID는 커밋한 트랜잭션의 ID다.

실행 메타데이터와 행 소속은 기존 `collection_runs`와 독립적으로 보관한다. 기존 최근 3회 XML 보관 정책으로 옛 실행이 정리돼도 서비스·관측 시각·중복 행·원문 버전의 관계가 남는다. 이관된 월의 현재 실행은 `metadata`의 `molit_trade_month:<지역>:<월>`에도 기록해 월 참조가 사라지는 오류를 검출한다.

수집 시작 시 기존 월 실행을 기억하고 저장 직전에 다시 확인한다. 다른 실행이 먼저 갱신했으면 이번 저장을 중단한다. 수집 실행·페이지·버전·현재 행·월 참조·ID 할당은 같은 트랜잭션에서 확정한다.

## 검증·실제 이관 순서

1. 최신 로컬 DB를 복사하고 거래 ID·원문·공급자 연결의 기준값을 저장한다.
2. 상세 API 기본 수집과 과거 기본 API 응답 읽기, 동일 응답 재수집, 중복 증감, 정보 보강, 취소·정정, 실패 롤백과 동시 갱신을 검증한다.
3. 복사본에서 분당구 2026년 7·9·10·11월을 수집한다. 기존 835건의 ID 보존과 최신 상세 응답의 실제 건수·공식 ID를 확인한다.
4. 과거 실행은 해당 실행의 원문 버전과 비교하고 현재 실행은 현재 거래 행과도 비교한다.
5. 로컬 기준 DB 적용 후 연결 감사와 공식 내보내기·검색·지도·빌드 검증을 수행한다.

전체 과거 월의 공식 ID 확보 범위와 로컬 승인 연결 이관 범위는 실제 결과에 따라 기록한다.

## 2026-11-11 실제 결과

최신 로컬 DB의 복사본에서 상세 API 4개월을 수집하고 같은 월을 한 번 더 요청했다. 이후 같은 수집기를 원본 로컬 DB에 적용했다.

| 분당구 계약월 | 기존 거래 | 현재 상세 거래 | 보존한 기존 ID | 신규 ID | 공식 ID가 있는 현재 거래 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2026-07 | 471 | 471 | 471 | 0 | 471 |
| 2026-09 | 179 | 179 | 179 | 0 | 179 |
| 2026-10 | 177 | 203 | 177 | 26 | 203 |
| 2026-11 | 8 | 25 | 8 | 17 | 25 |
| 합계 | 835 | 878 | 835 | 43 | 878 |

공식 단지 카탈로그는 169개다. 기존 835건의 원문을 이전 실행의 버전으로 모두 확인했다. 복사본 재수집에서는 878건의 ID가 모두 유지됐고 새 ID와 퇴역 ID는 0개였다. 대상 월 밖의 거래 해시와 대장·대장 건물·네이버 승인 연결·원천 연결·매물 스냅샷 5개 테이블의 해시도 같았다. 검증 파일은 `local/molit-provider-id-validation/verification.json`에 있다.

로컬 전체 거래는 신규 43건을 반영해 344,537건이다. 공식 ID가 관측된 현재 거래는 위 878건이며, 나머지 343,659건은 과거 월의 추가 수집 대상이다. 로컬 승인 연결 기준본을 버전·해시로 전달하고 클라우드의 과거 기준이 이를 대체하지 못하게 하는 후속 구현은 [로컬 기준본 전달](local-apartment-baseline.md)에 기록했다.

상록마을의 공식 ID는 우성 `41135-60`, 라이프1차 `41135-58`, 라이프2차 `41135-226`, 보성 `41135-59`, 임광 `41135-61`이다. 이 번호와 로컬 대장·네이버 승인 연결을 구분해 저장한다.

```powershell
pnpm data:molit:collect --database local/molit-provider-id-validation/working.sqlite3 --region-code 41135 --month 202607 --month 202609 --month 202610 --month 202611
```

```sql
SELECT trade_id, provider, provider_apartment_id, run_id
FROM molit_trade_identities
ORDER BY trade_id;

SELECT provider_apartment_id, name, dong, jibun, observed_at
FROM molit_apartments
ORDER BY provider_apartment_id;
```

공식 ID는 공개 전체 JSON·SQLite의 원문과 월별 브라우저 자료의 `raw.aptSeq`에 보존된다. 브라우저 자료에서 이 필드를 삭제하고 파일명·해시를 다시 만들어도 검증이 실패하는 회귀 검사를 추가했다.

`pnpm test:data` 38개, 서버·자동화 테스트 20개, 아파트·주거 연결·일일 수집 관련 테스트 73개가 통과했다. 복사본의 공식 내보내기는 344,537건을 검증했다. 원본 로컬 DB 적용 후 공통 식별 정보를 재구성하고 연결 감사를 다시 수행했다.

로컬 기준 DB의 공식 내보내기, `pnpm build`의 빌드 전후 데이터 검사, `pnpm data:verify`, `pnpm check:publish`를 통과했다. 전체 344,537건·3개 구·760개 월별 파일·942개 구·월의 현재 원천 이력을 확인했고 공개 파일 420개를 검사했다. 로컬 미리보기의 HTTP 응답에서도 대상 4개월의 878건 모두에 `raw.aptSeq`가 있음을 확인했다. Codex 브라우저 패널 열기 요청은 `queued` 상태다.
