# 공식 단지 연결 이관과 조회 복구

2026-11-14 사용자 요청에 따라 삼성1차와 같은 공식 ID 보강 후 조회 누락을 로컬에서 수정했다. 커밋·푸시·운영 배포는 수행하지 않았다. 네이버 매물 수집과 표시 중단 상태는 유지한다.

## 복구한 연결과 결과

기존 코드가 기준본의 공급자 연결을 일부 월에서 관측한 `raw.aptSeq`로 구성해, 169개 번호만 포함했다. 이후 상세 API로 수집한 다른 단지의 번호가 승인표에 없어 기존 거래도 미확정으로 배정됐다. 이전 진단은 [단지별 조회 누락 기록](trade-query-regression-2026-11-13.md)에 있다.

공식 단지 연결을 `apartment_molit_sources`에 분리했다. 각 행은 `provider_apartment_id`, `source_entity_id`, `evidence_json`, `verified_at`를 보존한다. 내부 원천 단지 참조는 기존 조회 범위의 참조이며 공식 단지 ID를 대신하지 않는다. 승인표에는 네이버 번호나 개별 거래 ID를 공급자 단지 ID로 저장하지 않는다.

로컬의 계약 지역·월·일·단지명·법정동·지번·가격·면적·층·준공연도·해제 상태가 모두 같은 계약을 근거로 593개 공식 번호를 확인했다. 관측 파일의 해시·지역·건수와 원문 정규화 값을 검사한 뒤 로컬에서 적용했다. 연결 충돌과 근거 없는 번호는 이 자료에서 0개였다. 모호한 연결은 자동 승인하지 않으며 기존 승인도 지우지 않는다.

배포 자료 344,779건의 원천·배정 복사본에서 이전에 조회됐던 동일 계약을 대조한 결과는 다음과 같다.

| 지역 | 복구한 기존 조회 행 | 같은 계약의 추가 누락 |
| --- | ---: | ---: |
| 수원시 영통구 | 3,648 | 0 |
| 성남시 분당구 | 381 | 0 |

이는 원천 거래를 새로 만들거나 다른 단지에 복제한 수가 아니다. 원천에 존재하던 계약의 로컬 확정 조회 범위를 복구한 수다. 이전부터 주소·건물 구분이 미확정이었던 거래는 이 숫자에 포함하지 않는다.

## 추가 검토와 재발 방지

`baselineTradeBinding`은 같은 공식 번호가 있어도 다른 지번으로 넘어가지 않는다. 같은 지번의 다른 기존 원천 단지 이름으로 충돌하는 경우도 미확정으로 남긴다. 승인된 번호의 이름 표기만 달라지고 주소 범위가 같으며 기존의 다른 단지와 충돌하지 않는 경우에는 기존 연결을 유지한다.

배정 캐시에는 계산 방식 버전을 포함했다. 기준본 해시가 같더라도 이전 계산 방식의 캐시는 다시 만든다. 구버전 캐시가 수정된 조회 결과를 가리는 경우를 검사했다.

`assertMolitSourceCoverage`는 공식 ID가 보강된 뒤 기존에 허용된 조회 범위가 미확정으로 내려가는지 확인한다. 연결 누락·범위 충돌이 있으면 내보내기 전에 실패하고 이전 공개 manifest를 보존한다. 알려지지 않은 새 단지를 이름·주소로 임의 승인하지 않는다.

GitHub 워크플로는 수집 후 `check-molit-source-coverage.mjs`를 실행하고 결과를 `local/data-validation/molit-source-coverage.json`에 보존한다. 직접 `exportData`를 사용하는 호출에도 같은 검사가 적용된다. 검사 실패를 빈 거래나 정상 수집으로 바꾸지 않는다.

기준본에는 승인 테이블과 조회용 공급자 목록을 함께 보존한다. 두 목록이 다르면 해시를 다시 계산했더라도 설치를 거부한다. 설치 후 승인 테이블도 다른 로컬 확정 자료처럼 읽기 전용이다. 새 기준본 생성 시 더 이상 참조하지 않는 이전 압축 기준본은 정리한다.

## 원천과 기존 확정 자료 보존

원본 로컬 DB의 복사본에서 먼저 연결 적용·공식 내보내기·기준본 생성을 수행했다. 원본 적용 전후 15개 테이블의 행 수와 전체 행 해시를 비교했다. 실거래·수집 실행·원문 페이지·거래 버전·행 ID 원장·대장·건물·필지·네이버 연결·매물 관측이 모두 같았다. 새 승인 연결 테이블만 추가했다.

편집 가능한 로컬 원본에는 동결 기준본을 설치하지 않았다. 로컬 원본의 거래 344,537건과 수집 이력 942개 구·월을 보존했다. 최신 클라우드 DB를 오래된 로컬 DB로 교체하지 않았다.

별도의 공개 자료 검증용 DB에는 배포 원천의 344,779건과 동일한 ID·원문을 넣고 새 기준본을 설치했다. 설치 전후 거래 전체 해시가 같았고 공식 내보내기·검색·지도 자료 검사도 수행했다. 이 검증용 DB는 공개 원천의 복사본이며 클라우드의 비공개 XML 수집 이력 DB를 복원한 것이 아니다.

최종 기준본은 `c0b8b91cb64cc775f55bb28f7a3fc10558f21bfd3e4fb52a910856706e365775`다. 공식 연결 593개를 포함하며, 네이버 대상 469개와 기존 확정 연결 389개는 보존했다.

## 로컬 연결 검토와 기준본 전달

관측 폴더에는 검증한 공개 `data/manifest.json`과 그 manifest가 지정한 구별 원천 JSON이 필요하다. 아래 경로는 이번 검증 자료다.

```powershell
pnpm data:molit:link --observations local/trade-deployment-audit/2026-11-13/data/manifest.json
pnpm data:molit:link --observations local/trade-deployment-audit/2026-11-13/data/manifest.json --apply
pnpm data:identities
pnpm data:export
pnpm data:baseline:create
pnpm data:baseline:check
```

관측 자료가 없어도 기존 로컬 상세 원문에서 확인되는 번호는 검토할 수 있다. 이 명령은 GitHub Actions와 기준본이 설치된 DB에서는 연결을 확정하지 않는다. `--database`로 편집 가능한 검증 복사본을 지정할 수 있다. 적용을 반복해도 이미 확정한 연결의 근거·시각과 거래 행은 바꾸지 않는다.

동결 기준본을 설치한 별도의 수집·검증 DB는 다음처럼 검사한다. 원본 로컬 DB에 `data:baseline:apply`를 실행하지 않는다.

```powershell
pnpm data:molit:coverage --database local/molit-connection-repair-2026-11-14/published-view.sqlite3
```

## 검증 자료와 한계

최종 코드에서 Node 검사 363개와 아파트·대시보드·주거 이력·공유 URL 화면 검사 18개가 통과했다. 데이터 검사 묶음의 공식 ID 이관·범위 충돌·배포 차단·원천 보존 검사도 이 Node 검사에 포함된다. 공식 빌드의 앞뒤 검증, `data:verify`, `check:publish`, 연결 감사와 `git diff --check`를 통과했다. 로컬 원본 기준 검증은 344,537건·760개 월별 파일·942개 구·월 원천 이력을 확인했다.

추가 연결 감사에서 새 연결 해제나 기존 연결의 다른 단지 재배정은 없었다. 과거 연결 대조 방식의 범위 안 미확정 8항목은 그대로 보존했다. 원인은 다음과 같다. 이 집계를 공통 주거 배정의 부분 연결 상태와 합산하거나 모두 새 조회 버그로 해석하지 않는다.

| 기존 대조 미확정 항목 | 남은 확인 |
| --- | --- |
| 수내동 푸른마을(벽산) | 거래·대장 준공연도 1992·1993 차이 |
| 수내동 푸른마을(쌍용) | 도로명 후보와 확정 명칭·단지번호 충돌 |
| 정자동 정든마을(2단지)(동아) | 도로명 후보와 확정 명칭·단지번호 충돌 |
| 동천동 루체스타 | 현 대장에 대응하는 지번·도로명 후보 없음 |
| 동천동 동천센트럴자이 | 원천 지번 `BL-`, 도로명주소 없음 |
| 동천동 동천자이·한화포레나수지동천 | 원천 지번 `가-`, 도로명주소 없음 |
| 신봉동 에버하임 | 현 대장에 대응하는 지번·도로명 후보 없음 |

별도로 공통 주거 배정에는 원천 전체 내역과 주소·건물별 내역을 구분해야 하는 부분 연결 4개가 남아 있다. 장안타운(건영), 효자촌(미래타운), 대진, 벽산블루밍이다. 수지신봉현대빌라트는 독립적인 건물 소속 근거가 부족한 상태다. 이 자료는 원천 조회에 보존하고 증거 없이 특정 주소 구획에 복사하지 않았다. 해당 상태는 이번 공식 ID 보강으로 새로 발생한 회귀와 구분한다.

검증 자료는 Git 제외 경로 `local/molit-connection-repair-2026-11-14/`에 보존했다. `preservation.json`은 로컬 원본의 기존 15개 테이블 보존, `query-verification.json`은 지역별 복구·누락 대조, `provider-coverage.json`은 공식 ID 보강 거래 41,072건의 배포 전 검사를 기록한다.

`preview-verification.json`은 실제 미리보기 HTTP 서버에서 브라우저용 로더 `loadDistrict`를 실행한 결과다. 19개 자료 요청에서 검색 세대·월별 해시·주거 배정을 검증했고 세 단지의 최근 20건을 조회했다. 네이버 매물 요청은 0건이다. 미리보기는 `http://127.0.0.1:5174/`에서 배포 수집 자료 복사본을 사용한다.

검증 중 제어 가능한 브라우저 연결이 없어 화면의 시각 검사는 수행하지 못했다. 화면 테스트와 실제 자료 로더 검사를 시각 검사로 보고하지 않는다. 운영 사이트는 새 커밋·푸시 후 클라우드 수집 DB에 기준본을 설치하고 재배포해야 바뀐다.
