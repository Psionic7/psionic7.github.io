# 네이버 단지 연결 테이블과 매일 매매 광고 수집

실거래 원천 단지와 네이버 단지의 연결을 한 번 검증해 SQLite에 저장한다. 매일 수집은 저장된 번호로 바로 들어간다. 좌표는 초기 후보 탐색과 주소 검증을 보조하며, 최근접 단지라는 이유만으로 연결하지 않는다.

## 구현 계획

- [x] 기존 공통 아파트 ID를 유지하면서 원천 단지와 수집 대상을 여러 관계로 연결한다.
- [x] 실제 네이버 좌표·주소·검증 근거를 별도 테이블에 저장한다.
- [x] 매물 목록 수집 전에 단지 연결을 저장해 목록 시간 초과와 연결 실패를 구분한다.
- [x] 매일 검증된 번호부터 수집하고, 신규·주소 변경 대상만 다시 확인한다.
- [x] 검색 미확정 결과를 보존하고 주간·명시적 재시도를 제공한다.
- [x] 중개사별 광고를 보존하고 동일주소 광고 메타데이터를 표시한다.
- [x] 기존 자료의 좌표 확인과 실제 데이터 감사를 수행한다.

## 저장 구조

`apartment_naver_matches`는 수집 범위의 안정적인 ID를 기본키로 사용한다. 네이버 번호, `pending/verified/review/unmatched` 상태, 실제 관측 JSON, 공식 위치와 대조한 근거, 최초 연결·최근 검증 시각을 저장한다. 공식 출입구의 기대 좌표를 네이버 좌표에 복사하지 않는다. 관측 좌표가 없는 과거 연결은 `pending`이다.

`apartment_naver_sources`는 실거래 원천 단지 ID와 수집 대상 ID를 연결한다. 주소 구획·동 범위와 대장 연결 상태를 별도로 저장한다. 한 원천 단지가 여러 네이버 단지를 포함하거나, 같은 네이버 단지를 여러 원천 단지가 참조할 수 있다. 대장 건물 연결이 미확정이어도 시장 단지 연결은 독립적으로 검증할 수 있다.

`apartment_naver_source_connections`는 두 테이블을 결합한 활성 관계 뷰다. 삭제되거나 범위에서 빠진 관계는 비활성으로 남긴다. 원본 거래 테이블과 공개 원본 SQLite 스키마는 바꾸지 않는다. 연결 테이블은 기존 암호화 작업 DB 백업과 함께 GitHub Actions에 전달된다.

`automation/naver-verified-matches.json`은 실제 관측으로 검증한 공개 단지 연결과 검색 미확정 상태의 초기 자료다. 새 작업 DB는 대상 범위 해시가 일치하고 기존 시도가 없는 연결만 가져온다. 확인된 연결은 공통 주소 검증과 실제 관측 좌표를 다시 확인한다. 기존 미확정·재검토·검증 상태를 초기 자료로 덮어쓰지 않는다. 이후 자동 실행은 암호화된 작업 DB의 연결을 사용한다.

## 매일 수행하는 동작

1. 실거래·대장·주소 갱신 뒤 공통 식별 정보에서 매매 아파트 수집 대상을 만든다.
2. 공식 주소·필지·출입구·단지 범위의 해시로 변경을 확인한다. 거래 행 수나 신규 신고 이름만으로 연결을 만료시키지 않는다.
3. `verified` 번호가 있으면 검색 없이 해당 번호의 매매 광고 전체 페이지를 수집한다. 실제 주소는 매번 검증한다.
4. `pending/review` 대상은 실제 상세 정보로 먼저 연결을 검증·저장하고 매물을 수집한다.
5. 검색 미확정은 매일 반복 검색하지 않고 마지막 검색 후 7일이 지나면 자동으로 다시 확인한다. 주소가 바뀌거나 명시적 재시도한 경우에도 확인한다.
6. 광고 페이지 시간 초과는 검증된 연결을 보존한다. 주소 불일치는 `review`, 검색 후보가 확정되지 않으면 `unmatched`다. 이전 광고와 그 수집 시각은 보존한다.

대장상 업무·오피스텔 구획만 있고 실거래 APT 원천도 없는 구획은 아파트 수집에서 제외한다. 공식 용도가 다른 실제 APT 신고 단지는 원천 분류와 공식 용도를 나누어 보존한다. 네이버 단지가 여러 도로명을 묶으면 같은 주필지·등록 이름과 해당 구획에만 속하는 실제 APT 광고 동 표기를 함께 확인한다.

네이버가 재건축으로 분류하는 아파트는 `JGC` 유형을 그대로 보존해 매매 광고에 포함한다. 실제 브라우저에서 수지삼성4차와 한성 등 단지의 상세 유형과 광고 유형이 모두 `JGC`인 것을 확인했다. 오피스텔 등 다른 유형은 포함하지 않는다.

## 기존 자료 확인 결과

2026-11-09 연결 테이블을 재실행해 472개 대상 중 391개를 실제 네이버 좌표·주소로 검증했다. 68개는 검색 미확정, 13개는 확인 대기다. 수집 범위 내 실거래 원천 단지 384개 중 350개가 하나 이상의 검증된 네이버 단지와 연결되고 34개는 검증된 연결이 없다. 연결된 350개 중 16개는 다른 관련 구획에 미확정 상태가 있어 범위 검토가 필요하다. 미확정은 광고가 없다는 뜻이 아니다.

검증된 대상은 네이버 번호 344개를 공유한다. 최신 저장 스냅샷에는 고유 광고 번호 20,062개가 있으며, 11개 대상은 전체 페이지를 확인한 결과 광고가 0건이다. 11월 8일 일일 수집 보고와 11월 9일 일부 단지 재관찰의 시각은 별도로 남긴다. 삼성래미안1차는 광고 38건, 동천센트럴자이는 광고 191건이다. 동천센트럴자이 광고 중 178건은 네이버 동일주소 광고 정보를 포함한다.

## 중복 광고

단지 연결과 주택 식별은 다른 문제다. 광고 번호별 원문·중개사·호가를 보존하며, 재수집과 여러 단지 조회에서 같은 광고 번호만 중복 제거한다. 동·면적·층·가격이 같아도 다른 호수일 수 있으므로 그 조합으로 광고를 합치지 않는다.

2026-11-09 실제 PC 브라우저 응답에서 `sameAddrCnt`, `sameAddrMinPrc`, `sameAddrMaxPrc`를 확인했다. 이 필드는 `providerSameAddress`로 저장해 광고 옆에 네이버 동일주소 광고 수와 호가 범위를 표시한다. 서로 겹치는 묶음일 수 있어 합산하거나 나눠서 실제 주택 수로 환산하지 않는다. 이 응답에는 광고 간 연결 식별자가 없어 독립 주택 수를 확정하지 않는다. 과거 관측에 정보가 없으면 추정값으로 채우지 않는다.

## 실행 명령

```powershell
# 저장한 관측을 검증해 테이블 구성. 네트워크 요청 없음
pnpm listings:match
# 기존 번호의 실제 좌표가 없는 연결을 한 번 확인. 매물 전체 재수집 없음
pnpm listings:match --refresh-known --python ../insane-search/.venv/Scripts/python.exe
# 검증된 공개 관측을 GitHub Actions의 초기 연결 자료로 저장
pnpm listings:match --write-seed
# 미확정·재검토 대상만 다시 검색
pnpm listings:match --retry-unmatched --max-targets 20 --python ../insane-search/.venv/Scripts/python.exe
# 한국 날짜별 매매 광고 수집. 기존 실거래 자동 작업도 같은 함수를 사용
pnpm listings:daily
```

연결 감사 결과는 `local/data-validation/naver-matches.json`과 같은 이름의 Markdown에 저장한다. Markdown은 확인된 연결이 없는 원천 단지와 일부 관련 구획이 미확정인 단지를 나눠 표시한다. 매물 수집일과 연결 검증일은 독립적이다. 연결 메타데이터만 확인하고 과거 매물을 오늘 수집한 것으로 표시하지 않는다.
